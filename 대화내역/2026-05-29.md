## 2. 신DB 스키마 함정 — 사원 테이블은 `accounts`

* 초기엔 `users`로 사원을 조회 → 빈 결과. 직접 접속 분석 결과:
  * 실제 사원 테이블은 **`accounts`(59건)**. `users`(59건)도 있으나 앱·부속테이블은 `accounts` 기준.
  * **모든 부속 테이블 FK가 `accounts(id)` 참조** (user_status_history, user_family_members, user_vehicles, user_certifications, user_career_history, user_rewards_punishments). 마이그레이션 SQL 텍스트(`REFERENCES users(id)`)와 불일치.
  * `users`엔 `rank` 컬럼 부재 → `select(...,rank,...)` 시 PostgreSQL이 `rank()` 집계함수로 오인해 쿼리 전체 실패("WITHIN GROUP is required"). `accounts`엔 rank 존재.
  * 표시명은 `username` 우선(AuthContext 관례).
* TransferClient를 `accounts` 기준으로 전면 전환(목록·조인·본체 업데이트).

## 3. 탭 간 실시간 반영 (탭 재활성화 refetch)

* **근본 원인**: [AdminShell.tsx](file:///h:/DS_Material/src/components/layout/AdminShell.tsx)가 열린 탭을 모두 마운트한 채 `display:none`으로 숨기기만 함 → 숨은 탭은 mount 시점 데이터를 그대로 들고 있어 stale(새로고침 전 미반영).

* **적용**: AdminShell이 각 탭을 `TabActivationProvider(isActive=isVisible)`로 감싸고, [RequestsClient](file:///h:/DS_Material/src/components/requests/RequestsClient.tsx)(발주/신청/입고/출고)·[StockHistoryClient](file:///h:/DS_Material/src/components/stock/StockHistoryClient.tsx)(입고/출고관리)·[UsersClient](file:///h:/DS_Material/src/components/users/UsersClient.tsx)(사원관리)에 훅 연결.

## 4. 입출고 RPC 함수 복구

* 발주 리스트 입고완료 클릭 시 `Could not find the function public.add_transaction(...) in the schema cache` 오류.
* 진단: 신DB에 `transactions`·`materials`·`material_units` 테이블/컬럼은 완비됐으나, **입출고 RPC 함수 4개가 전부 누락**(add_transaction, delete_transaction_batch, mark_unused_return, scrap_material_unit) — 신DB 전환 시 함수 마이그레이션 미적용.
* 해결: 검증된 기존 마이그레이션 [migration-add-transaction-batch.sql](file:///h:/DS_Material/scripts/migration-add-transaction-batch.sql) → [migration-add-transaction-price.sql](file:///h:/DS_Material/scripts/migration-add-transaction-price.sql)을 신DB 직접 적용(idempotent). add_transaction은 코드(mock-router 12개 인자)와 시그니처 일치(단가 자동 기록). 적용 후 `NOTIFY pgrst, 'reload schema'`로 PostgREST 캐시 갱신. 입고처리 정상 확인.
