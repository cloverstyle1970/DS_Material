# 작업 대화 내역 — 2026-06-04

## 세션 개요

**자재관리·유지보수 두 사이트의 인증 일원화 + 호기 비통번호를 site_elevators.emergency_phone 단일 진리원으로 통일**. 어제(`a3d176b`)의 `password_hash` 통합이 실은 유지보수 사이트와 어긋나 있었던 것을 바로잡았다 — 유지보수는 Supabase Auth(`auth.users`, 이메일 키 `{id}@daesol.el`) 기반이고 `accounts.password` 평문 컬럼을 미러로 쓰는 구조였음. 평문 `password`로 다시 통일하면서 비번 변경/사원등록 시 Edge Function `admin-auth-ops`를 호출해 `auth.users`와 동기화하도록 보강. 후반에는 비상통화장치 데이터를 호기 단위 컬럼으로 옮겨, 현장 단위 `emergency_devices`(jsonb)와 옛 10컬럼을 폐기. 마지막으로 호기 목록 표에서 같은 비통번호 반복을 빈 칸으로 dedup.

## 1. 로그인 컬럼 일원화 재정정 — password_hash → 평문 password (커밋 `2856d32`)

* **재진단**: 어제 `password_hash`(SHA-256)로 통일했지만 실제 신DB `accounts`엔 평문 `password`도 함께 있고 58명 모두 채워진 상태. 유지보수 사이트(`daesol-sketch.github.io/index.html`)를 직접 보니 인증 흐름이 `get_user_auth_email(username)` RPC → `db.auth.signInWithPassword({email, password})` — 즉 **유지보수는 평문 password 컬럼이 아니라 Supabase Auth(`auth.users`, `${id}@daesol.el` 이메일)** 로 로그인 중. accounts.password는 비번 변경/생성/리셋 시 같이 갱신되는 미러였다.
* **결정**(사용자): 자재관리·유지보수 둘 다 평문 `accounts.password` 기준으로 통일. 단 유지보수가 보는 `auth.users` 측도 비번 변경 때마다 동기 갱신.
* **코드 변경**:
  - `src/app/login/page.tsx` — `password_hash` 매칭 → 평문 `password` 매칭, `hashPassword` import 제거.
  - `src/components/data/MyProfileClient.tsx` — 비번 변경 시 평문 `password` 읽기/쓰기.
  - `src/components/hr/EmployeeRegisterClient.tsx` — `password_hash: initialPwHash` → `password: form.initial_password`. 초기비번 기본값은 기존 `DEFAULT_PASSWORD = "000000"` 그대로.

## 2. admin-auth-ops Edge Function 동기화 + auth.users 14명 백필 (같은 커밋)

* `src/lib/supabase.ts` 에서 `SUPABASE_URL`/`SUPABASE_ANON_KEY` export.
* `src/lib/auth-ops.ts` 신설 — 유지보수와 동일한 `${SUPABASE_URL}/functions/v1/admin-auth-ops` 를 anon-key Authorization 으로 호출하는 얇은 래퍼. `createAuthUser`, `changeAuthPassword` 두 헬퍼.
* MyProfile 비번 변경 — `accounts.password` UPDATE 후 `changeAuthPassword(user.id, newPw)` 호출. EmployeeRegister 신규 등록 — accounts insert 직후 `createAuthUser(newUserId, initial_password)` 호출.
* **누락 보강**: `scripts/backfill-auth-users.mjs` — `accounts`에는 있는데 `auth.users` 매핑이 없는 사용자 자동 탐지 후 `admin-auth-ops create` 호출. 직접접속으로 점검해 보니 **14명 누락**(id 53~65, 69 — 자재관리에서 등록되며 동기화 안 됐던 신규 계정들). 백필 결과 잔존 누락 0건.
