## 1. 사원 등록 서명(싸인) 이미지 + 서명 필요 화면 등록 서명 재사용

### 요구사항

사원정보에 서명 이미지(png/jpg)를 등록해두고, 위험성평가·TBM·잔업승인 등 서명이 필요한 화면에서 매번 손으로 그리지 않고 등록된 서명을 재사용할 수 있도록 검토·구현.

### 검토 결과 (사전 확인)

기존에는 TBM 작성, TBM 참가자 확인, 위험성평가(PC/모바일), 잔업보고서 승인 — 모두 매번 캔버스에 손으로 서명하는 구조였고, 계정에 저장된 서명이 없었음. `accounts.photo_url`(프로필 사진) 패턴을 그대로 서명에도 적용 가능함을 확인.

TBM 작성폼은 작성자 1인이 여러 참가자 서명을 대신 입력받는 구조라, "등록된 서명 자동 사용"을 적용하면 본인 확인 없이 대리 서명이 가능해지는 리스크가 있음을 사용자에게 짚었고, 사용자는 **제한 없이 포함**하기로 결정(대신 "직접 서명으로 변경" 버튼으로 언제든 손 서명 복귀 가능하게 구현).

### 구현

| 항목 | 내용 |
|---|---|
| DB | `scripts/migration-add-employee-signature.sql` — `accounts.signature_url` 컬럼, `signatures` 스토리지 버킷(public read, 2MB, png/jpg/webp). Supabase pooler로 직접 적용 완료 |
| 등록 UI | `EmployeeRegisterClient.tsx`(관리자 사원등록), `MyProfileClient.tsx`(개인정보수정) — 프로필 사진과 동일 패턴으로 업로드/미리보기 필드 추가 |
| TBM | `TBMWriteForm.tsx` — 작성자·참가자별 "등록된 서명 사용" 버튼 (참가자 user_id 기준 조회) |
| TBM | `TBMParticipantConfirmModal.tsx` — 본인 계정 등록 서명 재사용 |
| 위험성평가 | `RiskAssessmentClient.tsx`(PC), `RiskAssessmentMobileClient.tsx`(모바일) — 서명 팝업에 동일 옵션 |
| 잔업보고서 | `OvertimeReportClient.tsx` — 승인 모달에 "등록된 서명으로 바로 승인" 버튼 |

모든 위치에서 등록된 서명이 없으면 기존처럼 손 서명만 표시, 있으면 버튼 추가 노출 — 기존 흐름 비파괴.

## 2. 라이트/다크모드 글자색 안 보이는 버그 수정

### 문제 1 — 라이트모드에서 잔업보고서 검색창 글씨 안 보임

`globals.css`에 Next.js 기본 템플릿 잔재인 `@media (prefers-color-scheme: dark)`가 있었는데, 이게 **OS 시스템 다크모드 설정**에 따라 `--foreground` CSS 변수를 앱의 실제 라이트/다크 토글(`.dark` 클래스, `ThemeContext`)과 무관하게 덮어씀.

→ OS=다크·앱=라이트 조합일 때: 배경은 흰색(앱 설정 따름), 글자색은 OS 설정 때문에 밝은 색 그대로 남아 흰 배경에 흰 글씨 = 안 보임.

`AccountSearchInput`(잔업 승인자 검색), 기간 검색 `<input type="date">`, 검색 드롭다운이 명시적 글자색 클래스가 없어 이 버그에 걸림.

**1차 수정**: 충돌하는 미디어쿼리 블록을 통째로 삭제 + 해당 입력창들에 `text-gray-900 dark:text-gray-100` 명시.

### 문제 2 — 1차 수정 후 다크모드에서 오히려 안 보임 (회귀)

미디어쿼리를 단순 삭제하니 `--foreground`가 항상 라이트값(`#171717`)으로 고정되어, 이번엔 다크모드 배경 위에 어두운 글자가 렌더링되는 반대 버그 발생.

**2차 수정**: CSS 변수를 아예 없애는 대신, 앱이 실제로 쓰는 `.dark` 클래스에 값을 연동:

```css
:root { --background: #ffffff; --foreground: #171717; }
.dark  { --background: #0a0a0a;  --foreground: #ededed; }
```

이제 OS 설정과 무관하게 `ThemeContext`의 `.dark` 클래스 하나만 보고 배경/글자색이 정해져 라이트·다크 모두 일관됨.

커밋: `a7a3e30 fix(ui): 라이트모드에서 OS 다크설정 시 잔업보고서 검색 글씨 안 보이는 문제 수정`, `8e9474e fix(ui): 다크모드에서 글자색이 라이트색으로 고정되던 문제 수정`

## 3. 팀구성관리 — 구성원 정렬 및 퇴사자 노출 버그

### 요구사항 변천 (대화 중 여러 차례 조정)

1. 조별 구성원을 직급 높은순 좌→우 정렬
2. (오해로 조별을 세로로 바꿨다가) 팀별 구성원은 위→아래, 조별 구성원은 좌→우로 최종 정리
3. 미배정 사원도 동일 정렬 적용
4. 동일 직급이면 입사일 빠른순으로 tie-break

### 구현 (`TeamCrewClient.tsx`)

- `ranks` 테이블 조회(`rankOrder` 맵: 직급명→sort_order, 낮을수록 높은 직급 — 대표=10 ... 사원=90)
- `sortByRank(list)` 헬퍼: 직급순 → 동일 직급 시 입사일 빠른순 → 이름순
- 팀 펼침 영역에 "👥 팀 전체 구성원 (직급순)" 패널 신규 추가 (세로 나열)
- 조 구성원 배지: `flex flex-wrap` 유지, `sortByRank` 적용 (가로 나열)
- 미배정 사원 표: `sortByRank` 적용

커밋: `1c083e4 feat(hr): 팀구성관리 구성원 목록을 직급·입사일 기준으로 정렬 표시`

### 버그 — 퇴사자가 미배정 사원으로 노출

사용자 제보: "박흥식은 퇴사자인데 미배정사원으로 나옴". 원인은 `accounts` 조회 쿼리에 `status='재직'` 필터가 빠져 있어 퇴사자도 함께 조회됐던 것. 다른 페이지(TBM 작성폼 등)와 동일하게 필터 추가.

커밋: `badbcdf fix(hr): 팀구성관리에서 퇴사자가 미배정 사원으로 표시되던 문제 수정`

수정 후에도 "여전히 보인다"는 제보가 있었으나, DB 직접 조회 시도는 사용자가 중단시켰고 이후 "로컬에서는 확인했어" → "확인완료"로 마무리됨. **다만 근본 원인 후보로, `accounts.status` 필드는 관리자가 개인정보수정 화면에서 직접 바꿔야 하는 별도 필드이고, "발령/재직상태 이력"(`user_status_history`)에 퇴직 기록을 남기는 것과는 별개라는 점을 확인함** — 만약 재발하면 해당 사원의 `accounts.status` 값이 실제로 "재직"으로 남아있는지 먼저 확인할 것.
