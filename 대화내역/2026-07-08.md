TBM등록에서 작업참가자 검색 입력 시 **"This page couldn't load" 크래시** 원인 규명 및 방어 처리. 인센티브 관리 페이지에 **검색 결과 엑셀 저장** 버튼 추가.

관련 커밋: `51560a0`, `09b51c3`.

## 1. TBM 작업참가자 검색 크래시 수정 (`51560a0`)

**증상:** TBM등록 화면에서 작업참가자 검색란에 글자를 입력하는 순간 `This page couldn't load` 오류 화면.

**원인:** `src/components/tbm/TBMWriteForm.tsx:151-157` `filteredParticipants` 계산에서 사용자 필터링:

```ts
u.name.includes(participantSearch.trim()) || u.dept.includes(participantSearch.trim())
```

`accounts` 테이블에 `username` 또는 `dept`가 **NULL인 계정**이 하나라도 있으면 첫 검색어 입력 즉시 `TypeError: Cannot read properties of null (reading 'includes')`이 던져지고, Next.js 클라이언트 에러 바운더리가 페이지 전체를 다운시킴.

**수정:**

```ts
// Before
(u.name.includes(q) || u.dept.includes(q))

// After
((u.name ?? "").includes(q) || (u.dept ?? "").includes(q))
```

- `UserMini` 타입도 실제 스키마 반영: `name: string | null; dept: string | null`
- 검색어(`q`)를 filter 내부에서 한 번만 trim해 재사용

**추가로 함께 커밋된 변경:** `IncentiveEntryClient.tsx` — 수정 모드에서 발행일 편집 가능 표시(하이라이트 + 안내 문구). 이번 세션 이전부터 워킹트리에 있던 미커밋 변경을 같이 반영.

## 2. 인센티브 관리 엑셀 저장 버튼 (`09b51c3`)

**대상 페이지:** `/accounting/incentive` — `IncentiveClient.tsx`

**구현:**

- 상단 헤더 우측에 `📥 엑셀 저장 (N건)` 버튼. 표시 건수 라벨 즉시 반영, 0건일 때 비활성화(에메랄드-300 처리).
- 현재 회사·지역·현장·기간 필터가 적용된 `visibleRows`를 그대로 xlsx로 export. 사용 라이브러리는 기존 `xlsx@0.18.5` (`PeriodStatsClient` 패턴 재사용).
- 컬럼: 발행일 · 회사 · 지역 · 현장명 · 계약내역 · 견적가 · 확정가 · 자재비 · Nego(40%) · 순수자재비 · 인센티브 · 담당자 · 비고
- Nego/순수자재비/인센티브는 `computeMetrics()` 결과를 소수점 둘째 자리로 반올림해 숫자로 저장 (엑셀에서 재계산 가능)
- 마지막 행에 **합계 행** 자동 삽입 (현장명 셀에 "합계")
- 파일명: `인센티브내역[_필터라벨]_YYYYMMDD_YYYYMMDD.xlsx`
  - 필터 미적용: `인센티브내역_20260701_20260731.xlsx`
  - 필터 적용: `인센티브내역_DS-화정_20260701_20260731.xlsx`
- 컬럼 폭(`ws["!cols"]`)도 지정해 열자마자 가독성 확보
