## 세션 개요

**구DB(`gwgzzsoknjulwwsmubju`) → 신DB(`bbnmxwpacdfqvicybhau`) 전면 전환.** 신DB가 `accounts`/`managed_sites` 기반으로 재설계된 별도 스키마임을 직접 접속 분석으로 확인하고, ① 데이터 병합·이전(테이블 생성 + FK 재매핑 + user_id 리맵), ② RLS 개방, ③ 화면별 코드 전환(로그인·현장·자재·데이터관리·견적·자재흐름·산업안전·공사·인사), ④ 스토리지 버킷 생성, ⑤ 발주전표 '무상' 기능 추가를 수행. 이후 **외부 배포(GitHub Pages)를 신DB로 전환**하면서 빌드 실패·로그인 실패(빈 키→헤더 공백→손상된 Secret)를 단계적으로 진단·해결하고, 대시보드 회사구분 집계까지 보정 후 원격 `master`에 11개 커밋 푸시 완료.

> ⚠️ 데이터 접근 인프라: anon key로는 DDL 불가 → `scripts/db-conn.mjs`(pg + pooler, `.env.local` 자격증명)로 postgres 직접 접속해 마이그레이션 수행. 작업 후 `.env.local`의 DB 비밀번호는 제거함.

## 7. 외부 배포(GitHub Pages) 신DB 전환 — 트러블슈팅

* 배포 구조: `.github/workflows/deploy.yml` (push→Actions build→Pages, `output: export`, basePath `/DS_Material`). DB 주소는 빌드 시 Secret에서 주입.
* **빌드 실패**: `scripts/site-import/*.ts` 인코딩 손상이 `next build` 타입체크를 막아 배포 중단 → `tsconfig.json` exclude에 `scripts` 추가로 해결.
* **로그인 실패 단계적 진단**:
  1. 배포 번들 anon key 비어있음 → supabase.ts에 키 기본값 추가
  2. `Headers: Invalid value`(Secret 키에 공백/개행) → sanitize 추가
  3. **401 Invalid API key**(Secret 키 값 손상) → **env 미사용·검증된 anon key를 코드에 고정**(공개 publishable 키, RLS 보호)으로 최종 해결.
* **PWA 매니페스트 404**: `layout.tsx`의 `manifest: "/manifest.json"`에 basePath 미적용 → production prefix 적용.
* 검증: 배포 번들 키 = 올바른 키 일치 + REST `HTTP 200` 확인. 외부 `황진한/000000` 로그인 성공 확인.
