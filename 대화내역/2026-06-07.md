# 작업 대화 내역 — 2026-06-07

## 세션 개요

**권한 모델 정비 + 모바일 UX 개선이 주축**. 가장 큰 건은 권한 버그 추적이었다 — "이종선(관리관리자)에게 세부권한을 다 줬는데 기능이 안 됨" 신고에서, 다수 관리 페이지가 세부권한(`menu:{href}:read|create|update`)을 무시하고 `isAdmin`(시스템관리자)으로만 하드 차단하던 구조를 발견. 이를 `hasMenuPermission(read)` 접근 + `canWrite(create||update)` 쓰기 가드로 전환했다. 또한 "비관리자"의 정의를 **보수일반·공사일반 권한그룹**으로 못박고(`isNonManager`), 금액 숨김 기준을 `isAdmin` → `!isNonManager`로 교체. 그 외 모바일 팝업(현장/호기별 투입현황·자재관리·공사일정), TabBar 햄버거 일원화, 로그인 기본 탭 `/me` 전환, 라이트모드 색 버그 등 다수.

커밋: `32f8850`, `4e42533`, `d9773e4` (+ 라이트모드 수정은 본 대화내역과 함께 커밋).

## 1. 개발 서버 기동 + `.next` 캐시 손상 복구

* `npm run dev` 백그라운드 실행이 Windows stdout 파이프 쓰기 오류(`errno -4094 UNKNOWN write`)로 크래시. Turbopack의 대화형 출력(커서 제어문자) 탓 → `CI=true`로 실행해 회피.
* 현장/호기 관리(`/site/units`)가 **404**. 원인은 첫 크래시가 `.next` filesystem cache 컴팩션 도중 발생해 `routes.d.ts` 등 캐시 손상. `.next` 삭제 후 재기동으로 해결(페이지·레지스트리는 정상이었음).

## 2. 사이드바 — `#` 자리표시 메뉴를 admin에게만 (커밋 `32f8850`에 포함)

* "조회 미체크인데 위험성평가·준비중이 계속 보임" 신고. 원인: `#`로 시작하는 자리표시 메뉴(`#safety-risk`, `#accounting`)가 `if (startsWith("#")) return true`로 **전원 노출**.
* `Sidebar.tsx`: `return user ? isAdmin(user) : false` 로 변경 → 비관리자에겐 숨김.

## 3. 현장/호기별 투입현황 (`SiteStatsClient`)

* **비관리자 금액 숨김**(처음엔 `isAdmin` 기준 → 후에 §8에서 `isNonManager`로 재정의): 입고·출고·수익금 금액 공란, 수량은 표시. 요약 카드는 수량 카드로 전환, 엑셀 다운로드 관리자 전용.
* **현장 클릭 → 자재별 표시**: 좌측 현장 행 클릭 시 우측 자재별 현황을 해당 현장으로 필터(`detailSite` 상태, 좌측 목록은 유지). 모바일에서는 우측 패널 대신 **팝업(바텀시트)**. `renderMaterialBody()`로 본문 공용화, `matchMedia(max-width:767px)`로 모바일 판정.

## 4. 자재관리 모바일 상세 팝업 (`MaterialsClient`)

* 모바일(<768px)에서 **자재코드·부품명 클릭 시 상세 팝업**(코드·규격·단가·재고·사진, 비조회전용은 수정 버튼). 데스크탑은 기존 행 선택 토글 유지. 셀에 점선 밑줄로 탭 가능 표시.

## 5. TabBar 모바일 햄버거 일원화 (커밋 `32f8850`)

* Header에만 있던 햄버거를 **TabBar(항상 표시)**로 이전 → Header 없는 탭(현장/호기 등)에서도 모바일 메뉴 열기 가능. Header의 중복 햄버거 제거.

## 6. 로그인 기본 진입 탭 → "내 대시보드"(`/me`) (커밋 `32f8850`)

* `login/page.tsx` 리다이렉트 2곳, `AdminShell` 탭 빈 상태 자동오픈, 루트 `app/page.tsx`·`(admin)/page.tsx` 리다이렉트를 `/dashboard` → `/me`로. `/me`를 AdminShell `isAlwaysAllowed`에 추가(비관리자 접근 보장).

## 7. 공사일정 모바일 보기 팝업 (커밋 `4e42533`)

* 일정 클릭이 곧 `openEditModal`(권한 없으면 아무것도 안 열림)이던 것을, 모바일에서는 **권한 무관 내용 보기 팝업**으로 분기(`viewSchedule`). 권한 보유자는 팝업에서 수정 모달로 진입. 데스크탑은 기존 유지.

## 8. 권한 버그 추적 — isAdmin 하드게이트 → 메뉴 권한 기반 (커밋 `d9773e4`)

* **신고**: 이종선(부서 관리팀, 그룹 관리관리자)에게 세부권한을 부여했는데 "메뉴는 있는데 권한이 없다고 나옴".
* **DB 직접 점검**(pooler 접속): 이종선 권한 80여 개 정상 저장, dept=관리팀 → `isViewOnly` false. anon은 RLS로 accounts/permission_groups 조회 차단(authenticated는 `USING true` 허용).
* **근본 원인**: 다수 페이지가 `if (!isAdmin(user)) return <차단>` 으로 세부권한을 무시. 사이드바엔 보이지만(read) 페이지가 막음.
* **수정**: `isAdmin` 하드게이트 → `hasMenuPermission(user, href, "read")` (admin은 내부에서 통과). 대상: 부서/직급, 사원등록, 재직상태, 팀구성, 인사이동, 사용자권한그룹, TBM 관리/마스터, 재고실사. (회사정보·회사차량·근무복관리·공정별공수표·견적설정/목록은 이미 `canRead` 패턴이라 미변경.)

## 9. "비관리자" 정의 규정화 + 금액 숨김 기준 교체 (커밋 `d9773e4`)

* **규정**(메모리 `rule-non-manager-definition`): "비관리자" = 권한그룹 **보수일반·공사일반** 소속자. 그 외(보수/공사 관리자, 관리일반/관리관리자, 시스템관리자)는 관리자급 → 금액 노출.
  - 그룹: 1=보수일반(34명), 2=보수관리자, 3=공사일반(9명), 4=공사관리자, 5=관리일반, 6=관리관리자, 7=시스템관리자.
* **구현**: `AuthUser.groupName` 추가 → 로그인·세션동기화 때 `permission_groups`에서 로드. `isNonManager(user)` 헬퍼(groupName ∈ {보수일반,공사일반}).
* 금액 숨김(`SiteStatsClient`·`StockHistoryClient`)을 `isAdmin` → `!isNonManager`로 교체. (입고관리 단가·금액도 비관리자 공란, 출고관리 공유 컴포넌트라 함께 적용.)

## 10. 읽기/쓰기 분리(쓰기 가드) (커밋 `d9773e4`)

* §8에서 read만 줘도 편집까지 가능했던 문제를 보강. 각 페이지 `canWrite = create||update`로 쓰기 컨트롤(추가·수정·삭제·토글·체크박스)을 숨김/비활성:
  - 부서/직급, 재직상태, 인사이동, 팀구성, 사용자권한그룹, TBM 관리/마스터, 재고실사.
  - 사원등록(순수 create 폼)은 쓰기 권한 없으면 "조회 전용" 안내.
* 클라이언트 가드(현 RLS는 `USING true`). 운영 전 서버측 RLS 강화 권장 — 미진행.
