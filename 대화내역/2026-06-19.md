## 1. 채번 race-condition — `next_doc_no` RPC + advisory lock (커밋 `355e2b2`)

### 진단

사용자 보고: "외부서버에서 `duplicate key value violates unique constraint "idx_purchase_orders_order_no"` 오류 발생"

`src/lib/document-no.ts:11-14` 주석에 race 가능성이 이미 명시되어 있었음:

```
동시 입력 시 SELECT MAX + 1 방식이라 race 가능성 존재 — 같은 prefix-YY-MM의
다음 번호를 두 클라이언트가 동시에 가져가면 두 번째 INSERT가 UNIQUE 위반.
호출부는 INSERT 실패 시 1회 재채번 재시도하는 패턴을 권장(현재는 미구현,
견적과 동일한 리스크 수용).
```

견적도 인라인 SELECT MAX 로직(`QuoteEntryClient.tsx:735-749`)으로 같은 위험.

### 해결 방향

사용자 선택: **DB 함수 + advisory lock** (가장 견고).

설계:

- `doc_seq(channel, period, next_seq)` 카운터 테이블 + `pg_advisory_xact_lock`으로 `(channel, period)` 단위 직렬화
- 채널 첫 호출 시에만 기존 테이블의 max를 백필 (기존 발주/견적 번호와 충돌 방지)
- 4채널(B/I/O/Q) 한 함수로 통합

```sql
CREATE OR REPLACE FUNCTION next_doc_no(p_prefix TEXT, p_date DATE DEFAULT CURRENT_DATE)
RETURNS TEXT
LANGUAGE plpgsql
AS $$
DECLARE
  v_period TEXT; v_width INT; v_head TEXT; v_seq INT; v_existing_max INT;
BEGIN
  IF p_prefix = 'Q' THEN v_period := TO_CHAR(p_date, 'YYYY'); v_width := 4;
  ELSIF p_prefix IN ('B','I','O') THEN v_period := TO_CHAR(p_date, 'YY-MM'); v_width := 3;
  ELSE RAISE EXCEPTION '알 수 없는 문서 prefix: %', p_prefix;
  END IF;
  v_head := p_prefix || '-' || v_period || '-';

  PERFORM pg_advisory_xact_lock(hashtextextended(v_head, 0));

  SELECT next_seq INTO v_seq FROM doc_seq WHERE channel = p_prefix AND period = v_period;
  IF NOT FOUND THEN
    -- channel 별 기존 max 백필 후 시작
    ...
    INSERT INTO doc_seq VALUES (p_prefix, v_period, v_seq + 1);
  ELSE
    UPDATE doc_seq SET next_seq = next_seq + 1 WHERE channel = p_prefix AND period = v_period;
  END IF;

  RETURN v_head || LPAD(v_seq::TEXT, v_width, '0');
END;
$$;
```

### 적용

신DB는 외부 담당자 관리지만 사용자가 비밀번호 제공 → `scripts/apply-migration.mjs` 로 직접접속 적용. 첫 시도에서 `Daeso7792!`로 인증 실패 → 사용자 정정 `Daesol7792!` (l 누락). 적용 후 메모리에 비밀번호 저장 요청.

클라이언트는 `generateDocNo`를 `supabase.rpc("next_doc_no", ...)`로 변경, `Q` prefix 추가. `QuoteEntryClient.tsx`의 인라인 채번도 `generateDocNo("Q", quoteDate)`로 통일.

## 2. UNIQUE 인덱스 해제 — 진짜 root cause (커밋 `b65c851`)

### 재발

`next_doc_no` 적용 후에도 같은 오류 재발 — race 가설이 틀렸음.

### 진단

`scripts/diag-order-no.mjs`로 DB 확인:

```
[중복 order_no]: 0건
[최근 order_no 행수]: 모두 lines=1, batches=1
[인덱스 정의]: idx_purchase_orders_order_no — UNIQUE INDEX
```

기존 발주들이 **모두 1행짜리**라 UNIQUE 충돌이 가려져 있었음. 코드 확인:

```ts
// PurchaseOrderEntry.tsx:286,332
const effectiveOrderNo = isEdit && orderNo ? orderNo : await generateDocNo("B", orderDate);
for (const r of valid) {
  await api.post("/api/purchase-orders", { ..., orderNo: effectiveOrderNo });  // 모든 행에 같은 값
}
```

한 발주서 = 한 `order_no`가 정상 디자인(batch_id로 묶음). UNIQUE는 잘못된 제약.

### 조치

`scripts/migration-doc-no-drop-unique.sql` — `idx_purchase_orders_order_no` / `idx_transactions_transaction_no` 두 UNIQUE 인덱스를 DROP 후 일반 인덱스로 재생성. `is_unique=false` 검증.

메모리 [[document-numbering-convention]] 에 이 함정 명시 — "별도 문서 간 race는 next_doc_no advisory lock으로 직렬화되므로 마지막 방어선으로서의 UNIQUE는 불필요. 새 채번 컬럼 추가할 때 같은 실수 반복 금지."

## 3. 발주서 인쇄 A4 맞춤 — portal 격리 + 행 분할 방지 (커밋 `ae65bce`)

### 진단

사용자가 인쇄 출력 PDF 첨부. 두 문제:

- 상단 약 70mm 공백 (`@page` margin은 18mm인데 실제는 훨씬 큼)
- 하단 특기사항(textarea) 잘림 — 위 여백 때문에 콘텐츠가 페이지 길이 초과

`PurchaseOrderEntry.tsx`의 미리보기 오버레이:

```tsx
{previewOpen && (
  <div className="fixed inset-0 z-50 ... po-preview-overlay">
    ...
    @media print {
      body * { visibility: hidden !important; }
      .po-preview-overlay, .po-preview-overlay * { visibility: visible !important; }
    }
  </div>
)}
```

`fixed inset-0` 이지만 AdminShell의 `position:absolute` 탭 컨테이너 안에 렌더 — 이 부모가 fixed의 **컨테이닝 블록**이 되어 페이지 박스로 빠져나오지 못함. `visibility:hidden`은 공간을 차지하므로 사이드바·헤더 영역만큼 콘텐츠가 아래로 밀림.

### 조치

`createPortal`로 body 직접 자식 렌더:

```tsx
{previewOpen && typeof window !== "undefined" && createPortal(
  <div className="fixed inset-0 z-50 ... po-preview-overlay">
    ...
  </div>,
  document.body
)}
```

인쇄 격리도 visibility → display 방식으로 깔끔하게:

```css
@media print {
  html, body { margin: 0 !important; padding: 0 !important; background: white !important; }
  body > *:not(.po-preview-overlay) { display: none !important; }
  .po-preview-overlay {
    position: static !important;
    background: white !important;
    overflow: visible !important;
    inset: auto !important;
  }
}
```

부가로 `PurchaseOrderPrintPaper`에 `print-color-adjust: exact` (회색 배경 유지), `tr break-inside: avoid`, 발송지 표 `.po-ship` 클래스 + `break-inside: avoid`, 화면 padding 18mm로 `@page` margin과 통일.

## 4. 견적서 인쇄 격리 + 양식 테두리 통일 (커밋 `05ab2cd`)

### 진단

사용자가 견적서 출력 PDF 첨부. 사이드바·탭바·로그아웃 버튼 등 AdminShell chrome이 그대로 인쇄에 찍히고, 견적 본문이 우측 좁은 영역에 끼임. 「직접인건비」같은 짧은 단어가 한 글자씩 세로로 표시되는 정도로 좁음.

두 사용처:
- `QuoteEntryClient.tsx` (작성 미리보기 모달) — 발주서와 같은 패턴, 같은 버그
- `QuoteDetailClient.tsx` (견적 상세 페이지 자체 인쇄) — 인쇄 격리 CSS 전무

### 조치

**QuoteEntryClient**: 발주서와 동일하게 `createPortal` + body 직접 자식 + display 격리.

**AdminShell**: 글로벌 `@media print` CSS 추가. 외곽에 식별 클래스 부여하고 chrome 숨김 + absolute 탭 컨테이너를 페이지 흐름으로 풀기:

```tsx
<div className="ds-admin-shell flex h-full ...">
  <Sidebar ... />
  <div className="ds-admin-main flex-1 ...">
    <TabBar />
    <div className="ds-admin-tabs flex-1 min-h-0 relative">
      {tabs.map(...)} // absolute inset-0, display:flex 또는 none
    </div>
  </div>
</div>

<style jsx global>{`
  @media print {
    .ds-admin-shell > *:not(.ds-admin-main) { display: none !important; }  /* Sidebar */
    .ds-admin-main > *:not(.ds-admin-tabs) { display: none !important; }   /* TabBar */
    .ds-admin-shell, .ds-admin-main { display: block !important; height: auto !important; }
    .ds-admin-tabs { position: static !important; }
    /* 활성 탭(inline display:flex)만 absolute → static */
    .ds-admin-tabs > div[style*="display: flex"],
    .ds-admin-tabs > div[style*="display:flex"] {
      position: static !important; inset: auto !important; overflow: visible !important;
    }
  }
`}</style>
```

견적 상세 페이지뿐 아니라 향후 다른 페이지 인쇄에도 자동 적용. portal로 옮긴 모달 인쇄(발주서·견적 입력)와는 무관 — portal은 body 직접 자식이라 셀렉터 적용 대상이 아님.

QuotePrintPaper에도 `print-color-adjust:exact`, `tr break-inside:avoid` 추가. 사용자 요청으로 두 양식 제목 박스 하단 `border-b-2(2px)` → `border-b(1px)`로 1px 통일.

## 5. 부가세 토글 동작 정비 + 출력 양식 다듬기 (커밋 `e9ceb27`)

### 직접인건비 적용 게이트 분리

사용자 보고: "견적서 작성에서 '직접인건비 적용'에 체크되어 있으면 인건비를 선택 적용할 수 있어야 돼."

`QuoteEntryClient.tsx`의 1공 단가·공수·간접/일관/이윤 입력 5개가 한 grid에 묶여 `laborEnabled`("요율 적용") 하나로만 활성/비활성. "직접인건비 적용"만 체크해도 1공 단가·공수를 입력할 수 없어 directLabor 계산이 실제로는 0.

게이트 분리:

| 필드 | 활성 조건 |
|---|---|
| 공/식 토글, 1공 단가, 공수, 작업 라인 | `directLaborOnly \|\| laborEnabled` |
| 간접/일관/이윤 입력 | `laborEnabled` 만 |

### 부가세 별도 = 부가세 미적용·미표시

사용자 요청: "합계에서 부가세별도가 선택되었을 때는 부가가치세는 적용하지 않고 출력양식에서는 표시하지 않음."

`QuotePrintPaper.tsx` 부가가치세 행과 합계 행을 `{vatIncluded && (...)}` 조건부 렌더. `QuoteEntryClient.tsx` 화면 합계 박스도 동일. 합계금액 안내 문구를 `위 금액은 부가세 {vatIncluded ? "포함" : "별도"} 금액임.`으로 동적 분기.

기본값: vatIncluded `false → true` (포함). 신규 작성 진입과 저장 후 폼 리셋 양쪽에서. 편집 모드 로딩(`!!h.vat_included`)은 그대로 — DB 저장값 존중.

### 양식 다듬기

- 고객승인 영역에서 "고객명" 행(customer_name·customer_phone) 제거, `rowSpan` 5→4.
- 승인자 행 셀 높이 `h-[72px]`로 키워 서명·인감 공간 확보.

## 6. 발주참조번호 입력·표시 일원화 (커밋 `a8c029c`)

### 진단

사용자 보고: "이전 발주서 작성시 주문참조번호 'MNG2026MMNNN'으로 된 번호를 사용했었는데 지금은 안보여."

DB 확인 (`diag-order-ref.mjs`):

```
[MNG 태그 발주 통계]: 108건, oldest 2026-05-12, newest 2026-06-18 04:39
[샘플]: order_no=null, note='[MNG2026060450]' 등
```

자재관리 시스템이 자동채번(`order_no`)을 도입한 후에도 다른 경로(아마 외부 유지보수 사이트 men.daesol.kr)로 옛 형식이 어제까지 계속 들어옴. `RequestsClient.tsx`의 발주번호 컬럼은 `o.orderNo || "-"`만 표시 → 옛 발주가 모두 `-`로 나옴.

### 1차 fallback (메모리 상태였음)

`src/lib/order-ref.ts` — `extractOrderRef(note)` 헬퍼. note 첫 `[xxx]` 태그를 반환하되 `[긴급]`/`[수리]` formType은 제외. 발주 리스트·엑셀·미입고 모달에 `o.orderNo || extractOrderRef(o.note) || "-"` fallback 적용.

### 사용자 정정 — 분리 관리

> "발주참조번호는 발주전표에서 입력할거고, 발주번호는 자동채번이라서 발주전표에 표시하지 않아됨. 발주리스트에서는 참조번호, 발주번호 각각의 체크박스를 만들고 표시여부를 선택하게 해줘. 입고전표에서는 '발주서참조'에서 리스트를 불러올때 발주참조번호가 표시가 필요. 출고전표에서는 '입고내역 참조'로 리스트를 불러올때 발주참조번호 표시가 필요"

> 추가: "발주서 출력 양식의 NO. 표시는 자동채번번호 표시"

방향:
- 발주서 **출력 양식**: 자동채번 발주번호(`B-YY-MM-NNN`) 그대로
- 발주서 **작성 화면(전표)**: 자동채번 표시 제거, 발주참조번호 입력란 신규
- 발주 리스트: 참조번호 / 발주번호 두 컬럼 분리 + 표시 토글
- 입고전표 발주서참조 모달: 발주참조번호 표시 (orderNo fallback 제거)
- 출고전표 입고내역참조 모달: 발주참조번호 컬럼 신규 (입고 note의 `발주 #N` → purchase_orders 일괄 조회)

### 적용

`PurchaseOrderEntry.tsx`:
- `orderRefNo` state + 입력란 (`예: MNG2026060450`)
- 자동채번 발주번호 표시 입력란 제거
- `parseNoteForEdit` 확장: 첫 [태그]가 긴급/수리가 아니면 `orderRefNo`로 복원
- `buildNote`: `[참조번호] [긴급] 메모` 형식 prepend → 외부 시스템과 동일 패턴

`RequestsClient.tsx`:
- `ORD_COLS`에 `participle: "ref" | "no"` 토글 속성 추가
- 두 컬럼 표시 boolean state + localStorage 보존 (`ds_ord_col_ref`, `ds_ord_col_no`)
