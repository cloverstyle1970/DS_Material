## 1. 시스템접속통계 페이지 신설 (`41b8603` + `9094103`)

### 1-1. 위치·접근제어

- 경로 `/data/access-stats`, 라벨 "시스템접속통계"(📊), 데이터관리 그룹
- **관리자 전용 3중 방어**:
  - `AdminShell` 라우트 가드 — `matchMenuHref` → 비관리자 리다이렉트
  - `Sidebar` 표시 필터 — `hasMenuPermission` 실패 시 항목 자체 숨김
  - `AccessStatsClient` 자체 `isAdmin` 검사 + 데이터 로드도 관리자 확인 후 실행
- **`PermissionGroupsClient` 트리에 의도적으로 미노출** — 관리자가 실수로도 다른 그룹에 이 권한을 부여할 수 없음. `permissions: ["admin"]`인 시스템 관리자만 통과.

### 1-2. 4카테고리 집계 소스

| 카테고리 | 소스 테이블 | 시각 컬럼 | 사용자 매칭 |
|---|---|---|---|
| 🔵 로그인 | `login_logs` (신규) | `created_at` | `user_id` FK |
| 🟣 메뉴방문 | `menu_visits` (신규) | `visited_at` | `user_id` FK |
| 🟡 자재관리 | `material_requests` · `purchase_orders` · `transactions`(입고/출고) · `uniform_safety_requests` | 각 요청/처리 시각 | FK |
| 🔴 유지보수 | `reports` (men.daesol.kr 공유 DB) | `completion_at` | `completion_handler` text ↔ `accounts.name` LEFT JOIN, 미매칭은 "미분류" |

유지보수 강조 지표는 **처리자(`completion_handler`)**로 확정. 처리 성과 지표에 적합.

### 1-3. login_logs (세션 시작 로그)

`scripts/migration-add-login-logs.sql` — user_id FK, username 스냅샷, created_at, user_agent, 인덱스 2개, RLS allow_all.

**옵션 2 세션 기반 로깅**:
- `signInWithPassword` 성공 지점의 단순 INSERT → **`AuthContext.pingSessionOncePerDay`** 로 교체
- `syncFromSession`(부팅 시)과 `login`(신규 로그인) 두 지점에서 호출
- localStorage 플래그 `ds_session_pinged:{userId}:{YYYY-MM-DD}` 로 하루 1회 제한
- **SSO로 유지보수→자재관리 이동한 경우도 커버** — signInWithPassword 없이 세션만 넘어오는 케이스에서도 자재관리 앱 부팅 시 기록됨

`login/page.tsx`의 명시적 INSERT는 제거 (중복 방지, AuthContext.login이 처리).

### 1-4. menu_visits (메뉴 방문 로그)

`scripts/migration-add-menu-visits.sql` — user_id FK, username, href, menu_label, visited_at, 인덱스 3개, RLS allow_all.

**옵션 A 신규 탭 오픈 기준** (탭 스위칭·재클릭 제외):

### 1-5. 4탭 UI

- **사용자별**: 사용자·부서·로그인·메뉴방문·자재관리(세부 액션 부기)·유지보수·합계·최근활동. 합계 기본 정렬
- **일자별/월별**: 버킷·카테고리별 카운트 + 활동사용자수(메뉴방문 제외 — 볼륨 크므로) + 합계. 빈 날/월도 0으로 표시
- **메뉴별**(핵심):
  - 컬럼: 메뉴·경로·방문수·유니크 사용자수·**상위 방문자**(top 3 이름·횟수)·최근 방문
  - 행 클릭 → 인라인 확장, 그 메뉴 방문한 사용자 전체 목록(사용자·부서·방문수·최근) 드릴다운
  - 한 번에 하나만 펼침, `▸`/`▾` 표시

각 탭 엑셀 다운로드. 사용자별은 자재관리 5개 세부 액션(자재신청·발주·입고·출고·근무복신청)까지 열로 분해.

## 4. TBM 참가자 완화 — 시도 후 취소 원복 (커밋 안 됨)

### 4-1. 원 요구
`tbm_participants.user_id NOT NULL` 이라 협력사 인원(사원 미등록자) 참가·서명 기록 불가.

### 4-2. 시도한 변경 (pooler 적용됨)
`scripts/migration-tbm-participants-external.sql`:
- surrogate `id BIGSERIAL PRIMARY KEY` 추가
- 기존 복합 PK `(tbm_id, user_id)` 제거, 새 PK는 `id`
- `user_id`·`user_name` NOT NULL 완화
- 부분 UNIQUE `(tbm_id, user_id) WHERE user_id IS NOT NULL` — 사원 중복 방지 유지, 협력사(NULL) 중복 허용
- `idx_tbm_participants_tbm` 조회 인덱스

코드:
- `TBMParticipant` 타입에 `id: number`, `user_id: number | null`, `user_name: string | null`
- `TBMWriteForm` validation 완화: 사원 매칭 강제 제거, 중복 검사는 `user_id != null` 만 대상, INSERT 시 `user_id ?? null`
- UI: 빨간 에러 대신 "🤝 사원 미등록 (협력사 인원으로 저장)" 노란 안내
- `TBMAdminClient`, `TBMMyList` render key `p.user_id` → `p.id` (null key 방지)

### 4-3. 취소 원복 (사용자 요청)
- pooler로 원복 스크립트 실행 — NULL 행 존재 확인 후 트랜잭션으로 스키마 완전 복원 (`id` 컬럼 삭제 · 복합 PK 재생성 · NOT NULL 재부여 · 인덱스 삭제)
- 코드 5파일 원상 (타입·validation·INSERT·안내문·render key)
- 마이그레이션 SQL 파일 삭제
- **남은 tbm 관련 diff는 TimeText import 경로만** (작업일지 삭제 작업의 일부, 참가자 완화와 무관)
