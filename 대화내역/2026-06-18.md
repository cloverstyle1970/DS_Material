## 5. 발주·입고·출고 자동채번 통일 (커밋 `9594de0`)

### 결정

| 종류 | 컬럼 | 형식 | 예시 |
|---|---|---|---|
| 발주 | `purchase_orders.order_no` | `B-YY-MM-NNN` | `B-26-06-001` |
| 입고 | `transactions.transaction_no` (type='입고') | `I-YY-MM-NNN` | `I-26-06-001` |
| 출고 | `transactions.transaction_no` (type='출고') | `O-YY-MM-NNN` | `O-26-06-001` |
| 견적 | `quotes.quote_no` (기존) | `Q-YYYY-NNNN` | `Q-2026-0001` |

- 1글자 prefix + YY + MM + 3자리 시퀀스 (월 999건 한도)
- 견적은 기존 형식 유지 (데이터 이행 위험 회피)
- 발주의 `orderRefNo` 수동 입력 완전 대체

### 마이그레이션 직접 적용

`scripts/migration-add-document-numbering.sql` 작성 → 사용자 승인 → pg 클라이언트로 직접 실행:

```sql
ALTER TABLE purchase_orders ADD COLUMN IF NOT EXISTS order_no TEXT;
CREATE UNIQUE INDEX IF NOT EXISTS idx_purchase_orders_order_no ... WHERE order_no IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_purchase_orders_order_no_prefix
  ON purchase_orders(order_no text_pattern_ops) ...;
ALTER TABLE transactions ADD COLUMN IF NOT EXISTS transaction_no TEXT;
...
```

검증 결과: `purchase_orders_order_no=1, transactions_transaction_no=1, new_indexes=4`.

### 채번 헬퍼 — `src/lib/document-no.ts`

```ts
export type DocPrefix = "B" | "I" | "O";

export async function generateDocNo(prefix: DocPrefix, date: Date | string = new Date()) {
  const yymm = yymmFromDate(date);
  const head = `${prefix}-${yymm}-`;
  const cfg = channelFor(prefix);

  let q = supabase.from(cfg.table).select(cfg.column)
    .like(cfg.column, `${head}%`)
    .order(cfg.column, { ascending: false }).limit(1);
  if (cfg.typeFilter) q = q.eq("type", cfg.typeFilter);

  const { data } = await q;
  let nextSeq = 1;
  if (data && data.length > 0) {
    const last = (data[0] as Record<string, string>)[cfg.column];
    const m = last?.match(/-(\d+)$/);
    if (m) nextSeq = parseInt(m[1], 10) + 1;
  }
  return `${head}${String(nextSeq).padStart(3, "0")}`;
}
```

견적의 `generateQuoteNo()` 와 동일 패턴 (SELECT MAX + 1).

### 동시성 한계

SELECT MAX + 클라이언트 +1 → 동시 입력 시 같은 시퀀스 가져갈 가능성. DB UNIQUE 인덱스가 마지막 방어선. 견적과 동일한 리스크 수용. 동시성 빈번해지면 PostgreSQL 함수(`SELECT ... FOR UPDATE`) 또는 RPC 업그레이드.

### add_transaction RPC와의 정합성

`add_transaction` RPC 서명을 바꿀 수 없어(외부 담당자 협의 필요), `supabaseAddTransaction` 이 RPC 호출 후 별도 UPDATE로 `transaction_no` 세팅. `unit_price` 처리와 동일 패턴 (mock-router.ts:392-429).

### UI 노출

- 발주서 양식 NO 표시 → 자동채번 번호 직결
- 발주리스트(RequestsClient) "발주참조번호" 컬럼 → "발주번호" (orderNo 사용, font-mono text-xs)

| `직접인건비 적용` | `요율 적용` | direct | indirect | overhead | profit |
|:---:|:---:|:---:|:---:|:---:|:---:|
| ⬜ | ⬜ | 0 | 0 | 0 | 0 |
| ⬜ | ✅ | **0** | 0 (=직접×rate) | 자재 기반 계산 | 자재+일관 기반 계산 |
| ✅ | ⬜ | 계산 | 0 | 0 | 0 |
| ✅ | ✅ | 계산 | 계산 | 계산 | 계산 |

`QuoteEntryClient.tsx:582-587`:
```ts
const directLabor   = directLaborOnly ? Math.round(laborUnitPrice * effectiveManhours) : 0;
const indirectLabor = laborEnabled    ? Math.round(directLabor * indirectRate / 100) : 0;
const laborSubtotal = directLabor + indirectLabor;
const overhead      = laborEnabled    ? Math.round((materialSubtotal + laborSubtotal) * overheadRate / 100) : 0;
const profit        = laborEnabled    ? Math.round((laborSubtotal + overhead) * profitRate / 100) : 0;
```

- `applyRates` 변수 제거 (의미 모호해져 사용 안 함)
- 직접인건비는 `directLaborOnly` 단독 의존, 간접·일관·이윤은 `laborEnabled` 단독 의존
- 직접인건비 체크박스 `disabled={!laborEnabled}` 제거 → 완전 독립
- 수정 모드 복원도 분리: `direct>0 → 직접 ON`, `indirect|overhead|profit>0 → 요율 ON`

### 양식 측 자동 공란 처리 (`QuotePrintPaper.tsx`)

`laborApplied` 판정을 `header.direct_labor > 0` 단독으로 변경 + 헬퍼:

```ts
const fmtOrBlank = (n: number) => (n > 0 ? fmtNum(n) : "");
const rateOrBlank = (n: number) => (n > 0 ? `${n}%` : "");
```

각 셀에 0 값이면 자동 공란 → 직접만 적용 / 요율만 적용 / 미적용 어느 케이스든 자연스럽게 노출됨.

### 검토 보고 (별도 수정 없음)

사용자가 "직접인건비 적용 체크되면 직접인건비만 적용되는지" 검토 요청 → 동작 정상 확인 보고. 마이너 관찰사항(수정 모드 복원 모호성, 체크 상태 잔존) 두 가지 함께 보고 — 사용자 판단으로 별도 수정 없음.
