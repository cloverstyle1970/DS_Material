## 2. 자재구분 변경 시 자동 재검색 (포커스 유지)

문제: 품목 입력 후 드롭다운이 뜬 상태에서 DS/TK/전체를 바꾸면 검색어를 다시 입력해야 함.

원인: ① 스위치 클릭 시 입력란 blur → `onBlur` setTimeout으로 드롭다운 닫힘. ② `matTypeFilter` 변경 시 재검색 미트리거.

해결:
- `renderMatTypeSwitch` 버튼에 `onMouseDown={e => e.preventDefault()}` → 포커스 유지.
- `matTypeFilter` 변경 effect 추가 — `searchOpen`인 행을 입력값 그대로 재검색. 최신 행은 `rowsRef`로 읽어 키 입력마다 재검색 도는 것 방지.

```ts
const rowsRef = useRef(rows); rowsRef.current = rows;
const matTypeInited = useRef(false);
useEffect(() => {
  if (!matTypeInited.current) { matTypeInited.current = true; return; }
  rowsRef.current.forEach(r => { if (r.searchOpen && r.material_name.trim()) searchMaterial(r.key, r.material_name); });
}, [matTypeFilter]);
```

## 5. 자재신청관리 호기 표기 버그 (`RequestsClient.tsx`)

진단: 현장명 옆 `({elevators.length}호기)`가 호기 **개수**를 표시 → "5호기" 1건 등록 시 "(1호기)"로 보여 등록값과 다르게 인식. (펼친 상세 표의 `호기` 컬럼은 원래부터 `item.elevatorName`으로 정확.)

수정: 개수 대신 실제 호기명을 표시하는 `fmtElevators` 헬퍼 추가, 모바일·데스크톱 요약 2곳에 적용.

```ts
function fmtElevators(elevators: (string | null)[]): string {
  const names = elevators.filter((e): e is string => !!e);
  if (names.length === 0) return "";
  if (names.length === 1) return names[0];        // (5호기)
  return `${names[0]} 외 ${names.length - 1}`;     // (5호기 외 2)
}
```

`filter(Boolean)` 결과가 TS상 `(string|null)[]`로 남는 문제는 헬퍼 내부 타입가드로 정리.

## 부수 1: dev 서버 잦은 Internal Server Error = 알약 실시간검사

검증 내내 `errno -4094 UNKNOWN: open '.next\dev\static\chunks\...layout.js'`가 라우트 무관하게 반복 → admin 페이지 잦은 500.

진단: Defender는 비활성, H:는 로컬 NTFS → **알약(ALYac) 실시간 감시 `AYRTSrv.aye`**가 webpack이 초당 수십 개 쓰는 `.next` 청크를 즉시 스캔·잠금 → Next 읽기와 sharing-violation. 해결: 알약 검사 제외에 `H:\DS_Material\.next` 추가 → `.next` 삭제 + dev 재시작 → UNKNOWN 0건, 12회 요청 200. [[troubleshoot-next-unknown-alyac]] 기록.

(보조 원인: 빌드 중 dev 서버를 여러 번 종료/재시작하면 `.next`가 반쯤 빌드된 채 손상 → 프로세스 트리 전체 종료 + `.next` 완전삭제 후 중단 없이 cold 빌드.)

## 부수 2: 신DB 사용량 점검 + 로그 bloat 정리

사용량 확인 결과 전체 196MB인데 실제 앱 데이터(`public`)는 33MB뿐. 나머지는 시스템 확장기능 로그:
- `net._http_response` 114MB — pg_net HTTP 응답 **bloat**(live 372건뿐)
- `cron.job_run_details` 35MB — pg_cron 실행이력 11만+ 건 누적(2분 주기 job)

정리(196MB→**50MB**, 146MB 회수): ① 7일 초과 cron 이력 101,086건 DELETE ② 두 테이블 VACUUM FULL(트랜잭션 밖 개별 실행) ③ 매일 04:10 `cleanup-cron-history` cron 등록. [[reference-db-bloat-cleanup]] 기록.
