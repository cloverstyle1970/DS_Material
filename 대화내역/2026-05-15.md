## 4. 인앱 알림 시스템 + /me 대시보드 (신규 모듈)

### 4-1. 요구사항 정리
- 공사요청 → 공사일정 등록 시 신청자에게 인앱 알림
- 사용자 개인별 대시보드 신설
- 알림 채널은 **인앱만** (카카오톡 알림톡은 추후)
- 신청자 식별: `requester_user_id` FK 컬럼 추가 (이름 매칭은 불안정)

### 4-2. DB (`supabase/notifications_and_requester.sql`)
- `construction_requests.requester_user_id INTEGER REFERENCES users(id) ON DELETE SET NULL` + 인덱스
- `notifications` 테이블 신설 (id, user_id, type, title, message, link, ref_type, ref_id, is_read, created_at)
- RLS enable + allow-all 정책 (내부 시스템 정책 일관성)

### 4-3. 백엔드 (`src/lib/mock-router.ts`)
- `ConstructionRequest`에 `requesterUserId` 필드, `NotificationItem` 타입 정의
- `insertNotification` 헬퍼 추가
- 라우트:
  - `GET /api/notifications?userId=&limit=` — 사용자 알림 조회
  - `PATCH /api/notifications/:id/read` — 단건 읽음 처리
  - `POST /api/notifications/read-all` — 전체 읽음 처리
- 트리거:
  - `POST /api/construction-schedules`: requestId 있고 신청자 user_id 있으면 `schedule_registered` 알림 발송
  - `PATCH /api/construction-schedules/:id`: 시작일/종료일/시간/현장/호기/내용이 실제로 변경됐을 때만 `schedule_updated` 알림 발송 (작업자·담당자·회사구분 변경은 제외)

## 5. 모바일 모달 미표시 문제 해결

### 5-1. 증상
- 공사요청 화면에서 "일정으로 등록" 클릭 시 PC에서는 모달이 뜨지만 모바일에서는 표시 안 됨

### 5-2. 원인 분석
- AdminShell의 컨테이너가 `overflow: hidden` (탭 absolute 레이아웃을 위한 처리)
- 모바일 Safari/Chrome에서 fixed-position 요소가 일부 환경에서 부모 컨테이너 transform/overflow 영향을 받는 케이스 존재
- Sidebar(z-50)와 모달(z-50)이 같은 z-index였음

### 5-3. 수정 (`src/components/common/DraggableModal.tsx`)
- `createPortal(..., document.body)` 사용 → 컴포넌트 트리와 무관하게 body 직속에 렌더링
- 기본 z-index를 50 → 60으로 상향 (사이드바보다 위)
- 커밋: `8db1d5c`
