#### DB 마이그레이션 (`scripts/migration-material-request-approval.sql`)
```sql
ALTER TABLE material_requests
  ADD COLUMN IF NOT EXISTS approval_status  text,
  ADD COLUMN IF NOT EXISTS approver_id      bigint REFERENCES accounts(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS approver_name    text,
  ADD COLUMN IF NOT EXISTS approved_at      timestamptz,
  ADD COLUMN IF NOT EXISTS rejected_at      timestamptz,
  ADD COLUMN IF NOT EXISTS reject_reason    text;
```

### 5. 승인자 선택 모달 (`ClaimEntryClient.tsx`)

#### 최초 구현
- 무상신청 저장 버튼 클릭 시 모달 오픈 (폼 유효성 먼저 검사)
- `accounts` 테이블에서 사원 목록 로드 (username 우선)
- 선택 후 "승인 요청 후 저장" → `approver_id`, `approver_name` 포함 DB 저장
- 선택된 승인자에게 알림 발송: "무상 자재신청 승인 요청"

#### 버그 수정 1 — 사용자 5명만 표시
- 원인: `accounts.name` NULL인 사원이 대부분, 실제 표시명은 `username`
- 수정: `select("id, username, name, dept")`로 변경, `username || name` 우선 사용

#### 버그 수정 2 — 검색 기능 추가
- 이름/부서로 실시간 필터링 입력창 추가
- 목록에 없으면 직접 입력 가능 (알림 미발송 안내)
- Enter 키로 1명으로 좁혀지면 자동 선택

#### 버그 수정 3 — Runtime TypeError `null.toLowerCase()`
- 원인: `approverList`에 `name: null` 항목 포함
- 수정: `a.name?.toLowerCase()` 옵셔널 체이닝, fetch 후 null name 필터링

#### 버그 수정 4 — 승인자 선택 후 저장 시 멈춤
- 원인: `submit(undefined, name)` 호출 시 `!approverId === true` → 모달 재오픈 순환
- 수정: 로직 완전 분리
  - `handleSaveClick()` — 저장 버튼 전용 (무상이면 모달만 오픈, 아니면 doSubmit 호출)
  - `doSubmit(approverId?, approverName?)` — 실제 DB 저장 전용 (모달 재오픈 로직 없음)
  - 모달 확정 버튼 → `doSubmit()` 직접 호출
- 추가 수정: 검색 타이핑 시 `selectedApproverId` 무조건 null 초기화 → 타이핑한 이름이 목록과 일치하면 ID 유지
