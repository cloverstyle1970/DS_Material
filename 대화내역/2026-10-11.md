### 2. 사이트 보안 취약점 분석 (DB 포함)

- **방법**: `.env.local`의 `TARGET_DB_*`로 신DB 직접 접속(pg)해 RLS·정책·권한·스토리지·함수 조회 + 공개 anon 키로 REST `count=exact` 호출(건수만, 데이터 내용 미출력)로 실제 노출 여부 검증
- 비밀번호 변경이 일어나는 공격(#2)은 실행하지 않고 코드로만 확인
- ⚠ 대화 중 DB 비밀번호가 채팅에 노출됨 → 조치 완료 후 교체 권장 (본 문서에는 기록하지 않음)

#### 🔴 치명적

1. **평문 비밀번호 61건 외부 공개**
   - `public.users` 뷰(owner `postgres`, `security_invoker` 없음 → RLS 우회)가 `accounts.password AS password_hash` 노출, anon SELECT 권한 있음
   - anon 키로 `/rest/v1/users` → 61건 조회됨
   - `accounts.password`는 평문이며 61건 모두 현재 Supabase Auth 로그인 비번과 일치 → 관리자 포함 전 계정 탈취 가능
2. **`admin-auth-ops` Edge Function 호출자 인증 없음**
   - `daesol-sketch.github.io/supabase/functions/admin-auth-ops/index.ts` — body의 `account_id`/`password`만으로 service role로 비번 변경
   - anon 키만으로 임의 계정 비번 변경 가능 (호출처: `src/lib/auth-ops.ts`)
3. **로그인 사용자 누구나 관리자 승격 가능**
   - `accounts` 정책 `accounts_authenticated_all` = `authenticated ALL USING(true)`
   - 본인 `permissions`를 `["admin"]`으로 UPDATE 가능. 권한 체크가 클라이언트에만 있음
4. **주민등록번호 평문 56건**

### 3. 권장 조치 순서 (미착수)

1. **즉시**: `users` 뷰 anon/authenticated REVOKE, `admin-auth-ops`에 JWT 검증 + admin 확인 추가, 전 직원 비번 초기화
   - ⚠ 유지보수 사이트(daesol-sketch)가 `users` 뷰·`admin-auth-ops`를 사용 중일 수 있으므로 영향 범위 먼저 확인
2. `accounts.password` 평문 컬럼 비우고 DROP, 비번 변경은 `supabase.auth.updateUser`로 전환
3. `accounts`는 본인 행만 수정, `permissions`·`ssn` 수정은 admin만 (RLS + 트리거 또는 RPC)
4. `{public}` 정책 40개 → `authenticated` 이상으로 축소, 급여·인사 테이블은 본인/admin만
5. 민감 버킷 private + signed URL, 업로드·삭제는 authenticated만
6. 주민번호 `pgcrypto`/Vault 암호화 또는 뒷자리 삭제
7. 조치 후 DB 비밀번호 교체
