## 세션 개요

**다크모드 가독성 전면 보강 + 비밀번호 인증 일원화 + 도움말 매뉴얼 편집 권한 + 계정 엑셀 추출 보안화**. 거래처 다크모드 입력칸 버그에서 출발해 16개 파일 다크모드 가독성을 병렬 감사·수정. 이후 두 사이트(자재관리·유지보수) 비밀번호 체계가 평문/해시로 갈라져 있던 것을 `password_hash`(SHA-256)로 일원화. 사이드바 권한 특례 제거, 도움말 매뉴얼 편집을 관리관리자 권한으로 개방(테이블·버킷 신규 생성), 계정 전체 엑셀 추출에서 비밀번호 컬럼 차단까지 진행.

## 6. 자재신청→발주→입고→출고→완료 로직 (설명)

* 병렬 에이전트 2갈래로 코드 추적. 핵심: **모든 재고 변동은 `add_transaction` RPC 하나가 단일 진리원**(`materials.stock_qty` UPDATE, FOR UPDATE 잠금).
* 흐름: 신청(status=신청) → 담당자 `출고처리` 시 재고 충분하면 출고 트랜잭션→완료 / 부족하면 RPC가 `재고 부족`으로 거부 → **수동 발주**(status=발주, 재고 변동 없음) → 입고완료 PATCH로 입고 트랜잭션·재고 증가 → 출고 시 차감·호기 기록 → (회수 필요건) 반납등록.
* 함정: 신청↔발주 자동 전이 없음(request_id 수동 연결), 다행 입출고는 행별 개별 RPC라 배치 비원자성, add_transaction 중복 정의(serial-tracking 버전이 정본).

## 7. 두 사이트 로그인 비밀번호 비교 → password_hash 일원화 (커밋 a3d176b)

* **진단**: `accounts`에 `password`(평문, 자재관리 로그인)와 `password_hash`(SHA-256, 유지보수 추정) 두 컬럼 공존. 58행 중 **57행 평문≠해시** → 같은 사용자가 사이트마다 다른 비번.
* **결정**(사용자): `password_hash`로 통일 + 유지보수 현재 비번 우선(기존 해시 보존).
* **코드**: login(입력 해시 후 password_hash 매칭), MyProfile(해시 검증·저장), EmployeeRegister(평문 INSERT 제거), mock-router(평문 NOT NULL 백필 제거). 초기비번 1234→000000, 최소 4→6자(사원등록·개인정보수정 통일).
* **DB**: `accounts.password` NOT NULL 제약만 해제(가역). 평문 컬럼 물리 삭제는 **유지보수 사이트 사용 여부 확인 후로 보류**.
* 메모리 [[architecture-password-hash-unified]] 기록.
* 검증: 황진한 등 57명 평문≠해시 목록 추출(테스트 계정 1개만 일치). 이들은 유지보수 비번으로 자재관리 로그인해야 함.
