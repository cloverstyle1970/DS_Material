## 1. 데이터 모델 (scripts/migration-risk-assessment.sql, 신DB 적용)

- `risk_categories` — 대분류. `doc_no`(DS-001 자동채번)·`sub_process`(중분류 공정)
- `risk_hazard_items` — 유해요인 마스터(= 위험성평가 항목 원본). `gubun`(중분류)·`hazard`·`accident_type`·`current_measure`·`default_present`(유/무 기본값)
- `hazard_surveys` — 기사 조사 1건. `site_name`(현장명)·`assess_type`(정기/수시)·`team`·`assessor`·`survey_date`·`user_id`→accounts·`status`(submitted/assessed)
- `hazard_survey_items` — 항목별 `present`(유/무) + 조사시점 스냅샷 + 위험성평가 입력(`result` 적정/보완/해당없음·`improvement` 개선대책·`improve_done_date` 개선완료일·`manager` 담당자)
- RLS 전체 개방(개발 표준), idempotent. 신DB 직접 적용(pooler).

> 관련근거(legal_basis)·중요위험등록번호(register_no)는 사용자 요청으로 UI 제거(DB 컬럼만 잔존).

## 2. 핵심 흐름 (KOSHA 체크리스트법: ①파악→②결정→③감소대책)

- 마스터(`risk_hazard_items`)가 유해요인조사표 전체 항목의 단일 원본
- 기사: 유해요인조사표 등록 → 대분류 선택 → 전체 항목 유/무 평가(마스터 `default_present` 미리채움) → 제출
- 관리자: 위험성평가 등록 → 제출 조사 선택 → **'유'(present=true) 항목만** → 확인결과·개선대책·완료일·담당자 입력 → 저장(status=assessed) → 인쇄
- 대장 2종: 제출/평가완료 내역 조회·상세·인쇄·삭제(또는 평가취소)

## 3. 시드/등록 데이터

- **보수점검(자체점검) DS-001** — 60항목(기계실/CAGE/카상부/승강장/PIT/HYD/MRL), 기본 유 24
- **고장처리 DS-002** — 93항목(기계실/CAGE/카상부/승강장/PIT/HYD/MRL/방재실), 기본 유 29
- 원본 엑셀(유해요인조사표_*.xlsx)에서 파싱, 재해형태는 본문 키워드 자동 추출, 유/무(F열)→`default_present` 보존

## 4. UI 컨벤션

- **구분별 아코디언**: 세 화면(조사표 등록·마스터·위험성평가) 모두 중분류별 펼치기/접기. 기본 **접힘**, ▾ 회전 아이콘 + **파란색 구분명** + 항목수, 전체 펼치기/접기 버튼
- **내역만 스크롤**: 표 본문 max-height + sticky 헤더(페이지 헤더·작성정보·제출버튼 고정)
- **1단 레이아웃**: 위험성평가·마스터를 2단→1단(세로) 배치
- 마스터 대분류 선택을 조사표 등록과 동일한 **드롭다운(대분류 공정)** 형태로 통일

## 5. 엑셀 업로드 등록 (유해요인조사 마스터)

- `HazardMaster.tsx` `importExcel()` — `import * as XLSX`(브라우저 ESM은 named export, default import 불가)
- 유해요인조사표 양식(NO/대분류/중분류/유해위험요인/유/무) 업로드 → 대분류 + 항목 일괄 등록
- DS-NNN 자동채번, 유/무→`default_present`, 재해형태 자동추출, 같은 이름이면 항목 교체(확인)
