## 1. 견적요청 목록 → 견적서 작성 진입 멈춤

### 1-1. 1차 원인 — 쿼리스트링이 붙은 href를 openTab으로 호출
- `QuoteRequestsListClient.goToQuoteEntry`가 `openTab("/quotes/new?fromRequest=N", ...)` 사용.
- `PAGE_REGISTRY`는 pathname-only 키라 매칭 실패 → `AdminShell`의 activeHref→URL 동기화에서 `router.push` 미호출 → 탭만 생기고 화면 변화 없음.

### 1-2. 1차 시도 — router.push로 교체
- `goToQuoteEntry`에서 `openTab` → `router.push("/quotes/new?fromRequest=N")` 변경, `openTab` import 정리.
- 빌드/타입 OK 했으나 사용자 보고 "탭은 새로 생기는데 열리지 않음" → 2차 원인 발견 단서.

### 1-3. 사용자 요청 — 팝업창 검토
팝업 방식 분석 후 옵션 4개 제시:
| 방식 | 평가 |
|---|---|
| 탭 시스템 그대로, sessionStorage로 우회 (권장) | AdminShell 가드 안 건드림, 좁은 패치 |
| AdminShell 가드 정확히 수정 | 근본 해결, 전역 영향 위험 |
| 팝업창 (window.open) | AdminShell이 팝업에도 떠서 UI 어색 |
| 팝업 + 별도 (popup) 라우트 그룹 | 가장 깔끔, 작업량 최대 |

사용자 선택: **sessionStorage 우회**.

### 1-4. 적용 — sessionStorage + CustomEvent
- `QuoteRequestsListClient`: `sessionStorage.setItem("ds:quote_from_request", id)` + `dispatchEvent("ds:quote_from_request_changed")` 후 `openTab("/quotes/new", "견적서 작성")`.
- `QuoteEntryClient`: `fromRequestId`를 state로 전환, 쿼리스트링 → sessionStorage → 이벤트 순으로 채움. 이미 마운트된 상태에서 재호출에도 갱신.
- 커밋: `1221d72`

### 1-5. 부가 — 견적작성중 미저장 분 재진입 허용
- 상세 패널에 `status === "견적작성중" && quote_id == null`이면 호박색 "✏️ 견적서 이어서 작성" 버튼 노출. 기존 "📝 견적서 작성"(신청 상태)과 별개로 추가.
- 커밋: `064ae35` (이후 묶음 커밋)

## 2. 견적 상세 클릭 시 탭이 안 열리는 문제 — 근본 원인

### 2-1. AdminShell.tsx:57 가드 분석
```ts
if (activeHref && activeHref !== pathname && PAGE_REGISTRY[activeHref]) return;
```
- 본래 목적: "탭 X 클릭으로 닫는 중" 상태에서 옛 탭 재추가 방지.
- 부작용: 다른 등록된 페이지에서 `router.push("...?query")`로 들어오면 `activeHref ≠ pathname` 조건만으로 `return` → 탭 추가 자체가 막힘.
- 영향 범위: `/quotes/detail?id=N`, `/quotes/edit?id=N`, `/invoice/tax?id=N`, `/invoice/delivery?id=N`, `/claim/quote-outbound?quoteId=N` 등 전반.

### 2-2. 정확한 해결 — prevTabsRef로 close-tab 전환만 잡기
- `useRef`로 직전 tabs 보관.
- pathname 매칭 tab이 직전 tabs에는 있었는데 현재 tabs에는 없으면 → 막 닫힌 케이스 → skip.
- 그 외 `router.push` 진입은 정상적으로 `openTab(pathname, label)` 호출.
- 새로고침 시 동작했던 이유: localStorage 복원 후 activeHref가 pathname과 자연스레 일치하기 때문.
- 커밋: `064ae35`

## 4. 견적서 저장 [object Object] 오류

### 4-1. 에러 메시지 추출 보강

## 9. 발주전표 등록 후 리스트 미갱신

### 9-1. 원인
- `RequestsClient` / `StockHistoryClient`는 탭 시스템상 한 번 마운트되면 그대로 유지.
- 데이터는 mount 시 한 번만 fetch. `router.push`로 돌아와도 재로딩 안 함.
- F7 경로는 `window.location.href` 하드 리로드라 보였지만 일반 저장 후 "리스트" 버튼 경로는 stale.

### 9-2. 수정 — 커스텀 이벤트로 재조회 트리거
- `PurchaseOrderEntry.save()` 성공 후 `dispatchEvent("ds:purchase_orders_changed")`. F7도 `router.push`로 통일(다른 탭 상태 보존).
- `InboundEntry.save()` 성공 후 `dispatchEvent("ds:transactions_changed", { detail: { mode: "입고" } })`.
- 수신부:
  - `RequestsClient`: `ds:purchase_orders_changed` / `ds:material_requests_changed` 리스닝 → 해당 데이터만 재조회.
  - `StockHistoryClient`: `ds:transactions_changed` 리스닝, `detail.mode`가 자기 모드와 일치할 때만 재조회.
- 커밋: `396fd78`
