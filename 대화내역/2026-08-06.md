## 1. 미사용 재입고 처리 흐름 (조사)

### 1-1. UI 진입점 — StockHistoryClient 출고 탭 처리 컬럼

각 출고 행이 상태별 3가지로 분기 (`src/components/stock/StockHistoryClient.tsx:617-646`):

| 조건 | 표시/동작 |
|---|---|
| `returnStatus === 'returned'` | "미사용반납" 또는 "폐자재회수" 배지(완료 상태) |
| `requiresReturn === true` (회수체크 O) | **폐자재회수** 버튼 → RPC `mark_return_completed` |
| `requiresReturn === false` (회수체크 X) | **미사용반납** 버튼 → RPC `mark_unused_return` |

회수체크 여부로 두 흐름이 **상호배타** 분리됨. `/returns` 페이지(ReturnsClient)는 폐자재회수 전용이며, 미사용반납은 재고이력 화면에서만 실행 가능.

### 1-2. mark_unused_return RPC 로직

`scripts/migration-add-unused-return.sql:63-137`:

1. 대상 출고 행 `FOR UPDATE` 잠금
2. 검증: `type='출고'` && `requires_return=false` && `return_status IS NULL` — 위반 시 에러 반환
3. 원출고 갱신: `return_status='returned'`, `return_type='unused'`, `returned_at/by_*`
4. **재고 복원**: `materials.stock_qty += v_tx.qty`
5. S/N 추적 자재면 `material_units.status='재고'`, `current_site/elevator=NULL` 원복
6. **감사용 입고 트랜잭션 자동 INSERT** — 동일 자재/수량/현장/S/N, `note='[미사용 반납 재입고] 원출고 #N …'`

폐자재회수(scrap)는 상태만 `returned` 로 마킹, 재고 무변동.

### 1-3. 확인된 한계

- **부분 반납 불가** — 출고 수량 전량 재입고. 일부 수량만 반납 옵션 없음.

- 원출고 ↔ 재입고 연결은 note 텍스트뿐(외래키 없음).
- 반납 완료된 출고 트랜잭션의 S/N 은 수정 불가(`mock-router.ts:1525`).
