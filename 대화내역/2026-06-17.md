## 3. 입고 수정 회귀 + 단가 보존 (커밋 `26bb4cb`)

### 회귀 버그 1: 발주가 미입고로 되돌아감

#### 재현 흐름

2. 발주리스트에서 "입고완료" 버튼 클릭

#### 원인 — 수정 모드 로딩에서 `orderId` 미복원

`InboundEntry.tsx:100` 의 row 로딩에서 `orderId: null` 고정. transaction `note` 컬럼에 `"발주 #N 입고완료"` 표준 태그가 박혀 있음에도(코드 주석 line 223-225) 파싱하지 않음.

저장 흐름에서 일어나는 일:
1. `batch DELETE` → `mock-router.ts:1789` 의 *"입고 transaction 삭제 시 발주 status 원복"* 로직이 자동으로 `purchase_orders.status = "발주"`, `received_at = null` 로 되돌림
2. 새 transaction INSERT — row 의 `orderId === null` 인 채로
3. `line 246-254` 의 status 재갱신 단계는 `orderIds.length === 0` 이라 SKIP
4. → 발주는 미입고로 회귀

#### 수정

```ts
function parseNote(note: string | null | undefined): { orderId: number | null; memo: string } {
  if (!note) return { orderId: null, memo: "" };
  const m = note.match(/^발주 #(\d+) 입고완료(?:\s*\/\s*(.*))?$/);
  if (m) return { orderId: Number(m[1]), memo: (m[2] ?? "").trim() };
  return { orderId: null, memo: note };
}
```

useEffect 안 row 로딩 시 `orderId: parsed.orderId`, `remark: parsed.memo`. `setReference(parseNote(target.note).memo)` 로 "참조" 입력란도 사용자 메모만 표시(태그 누출 차단). 미일치 패턴은 그대로 memo 취급(레거시 안전).

- **기본 숨김 + 토글 3종**: 재고변동·처리자·비고 모두 기본 숨김. 툴바에 체크박스 3개 ("재고변동", "처리자", "비고" — "표시" 제거). `ColDef.optional?: "note" | "processor" | "stock"` key 기반 매핑.
- **자재코드 셀 padding** (커밋 `463d96a` 별도): `pl-1 pr-2` → `px-2` 로 발주리스트와 일치 (사이 간격 8px).

### 용어 통일
- 7개 파일(코드·문서·스크립트)에서 **"불출" → "출고"** 전수 교체. 대화내역 history 는 보존.

## 9. 다크모드 sticky thead 비침 해결 (커밋 `bc3926d` + 후속 미커밋분)

### 원인 두 가지
1. **알파 50% 투명** — 일부 sticky thead 가 `dark:bg-gray-700/50` (알파 50%) 로 설정. 다크모드에서 스크롤된 행이 헤더 뒤로 비쳐 글씨 중복으로 보임. 라이트모드(`bg-gray-50` 불투명)는 영향 없음.
2. **thead 자체에 bg 누락** — 발주서/입고전표/출고전표 등록 화면(`PurchaseOrderEntry`/`InboundEntry`/`OutboundEntry`) 의 sticky thead 가 `<thead className="sticky top-0 z-10">` 으로 배경 없음. 배경은 `<tr>` 에만 박혀 있어 thead 영역 자체는 투명 → 다크모드 비침.

### 변경
- 리스트 측(`StockHistoryClient`/`RequestsClient`): `dark:bg-gray-700/50` → `dark:bg-gray-700` 일괄 + 누락된 sticky thead 에 `z-10` 보강 (커밋 `bc3926d`).
- 등록 측 3종: thead 에 `bg-[#e9ecef] dark:bg-gray-700` 보강 (작업트리 미커밋 상태 — 사용자 "확인완료" 후 처분 대기).

## 11. 후속 사항

- **등록화면 sticky thead bg 보강분(`InboundEntry`/`OutboundEntry`/`PurchaseOrderEntry`)** 작업트리 미커밋. 사용자 "확인완료" 응답 후 커밋 여부 미정.
- **AskUserQuestion 으로 사용자 결정 받은 옵션이 직후 더 큰 범위로 확장된 케이스 다수** — (입고전표 신청자 팝업컬럼→행컬럼→헤더, 출고전표 수령인 행→헤더, 거래명세서 인수자→납품자 등). 최종 형태가 누적된 변경의 합이라 코드 일관성 위해 정리된 커밋 메시지 사용.
- **사용자 padding 비교 질문** — 입고/출고 리스트가 동일 컴포넌트라 코드상 차이 없음을 답변. 사용자 보고는 빌드 캐시 또는 시각 인식 가능성 안내.
- **다른 페이지의 `dark:bg-gray-700/50` sticky thead** — 대시보드/반납/S/N이력/근무복/통계 등에 동일 패턴 잔존(이번 범위 외). 동일 비침 가능성 있으나 사용자 보고 미발생 — 향후 보고 시 일괄 처리.
