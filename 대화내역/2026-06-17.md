## 2. 푸시 Edge Function 호출도 하드코딩 상수 재사용 (커밋 `b9cbaf7`)

`src/lib/supabase.ts:4-7` 에 이미 의사결정 기록: *"배포 Secret 값 손상(붙여넣기 시 개행 끼임 등)으로 401이 반복돼, env를 읽지 않고 코드에 직접 고정"*. 그래서 일반 페이지의 Supabase 호출은 정상.

그런데 푸시 두 파일만 별도로 `process.env`를 직접 읽고 있었음:

- `PushNotificationToggle.tsx:30-31` — `callPushFn` 진입 가드의 `Supabase 환경변수 미설정` throw
- `notify.ts:36-38` — silent fail (Web Push 발사 자체가 차단)

GitHub Secrets 에 `NEXT_PUBLIC_SUPABASE_*` 가 등록 안 된 상태에서 빌드 → 빈 문자열로 박힘 → 가드 통과 못 함.

| `PushNotificationToggle.tsx` | `process.env.NEXT_PUBLIC_SUPABASE_*` 제거 → `supabase.ts` 의 `SUPABASE_URL`, `SUPABASE_ANON_KEY` import. 진입 가드도 제거(상수라 항상 존재) |

### 미해결: "전송 0건 (unknown)"

사용자 후속 보고: 위 수정 적용 후 "테스트 알림 보내기" → `{sent: 0}` 응답으로 alert. `push-send/index.ts` 분석:

```ts
// 3가지 반환 케이스
{ sent: 0, reason: "push_disabled" }      // accounts.push_enabled=false
{ sent: 0, reason: "no_subscription" }    // 구독 row 없음
{ sent: N, pruned: M }                    // ← unknown 케이스. reason 필드 없음
```

"unknown" = 구독 row는 있는데 webpush.sendNotification 전부 실패. 원인 후보 진단 가이드 안내:

1. **VAPID 키 페어 불일치** (★ 가장 가능성 높음) — 외부 담당자가 `MAT_VAPID_*` 별도 등록 시 본인 `.env.local` 키쌍과 다른 키쌍을 넣었다면 push gateway 가 403. Supabase Dashboard → Edge Functions → push-send → Logs 에 `[push-send] failed 403 ...` 확인.
2. **`subscription` jsonb 의 keys 손상** — `keys.p256dh`/`keys.auth` 누락 → staleIds 분류 → 다음 시도엔 `no_subscription` 으로 변함.
3. **endpoint 만료(404/410)** — 동일하게 staleIds 분류.

해결 분기:
- (a) 본인 키쌍으로 통일 — 외부 담당자에게 본인 `.env.local` VAPID 키쌍 전달, Edge Function 재시작
- (b) 외부 담당자 키쌍으로 통일 — 그쪽 공개키 받아 `.env.local`/GitHub Secret 교체 + 모든 사용자 구독 해제 후 재구독

→ (a) 가 작업량 적음. **사용자 후속 검증 대기**.

### 부가 — 테스트 알림 버튼 가시성

사용자 질문: "테스트 알림 보내기" 버튼이 외부서버엔 보이고 dev엔 없는데 정상인지.

## 3. 입고 수정 회귀 + 단가 보존 (커밋 `26bb4cb`)

### 회귀 버그 1: 발주가 미입고로 되돌아감

#### 재현 흐름
1. 발주서 작성
2. 발주리스트에서 "입고완료" 버튼 클릭
3. 입고관리에서 입고일자 수정 → 저장
4. → 발주리스트에서 다시 미입고로 표시, "입고완료" 버튼 재노출

#### 원인 — 수정 모드 로딩에서 `orderId` 미복원

`InboundEntry.tsx:100` 의 row 로딩에서 `orderId: null` 고정. transaction `note` 컬럼에 `"발주 #N 입고완료"` 표준 태그가 박혀 있음에도(코드 주석 line 223-225) 파싱하지 않음.

저장 흐름에서 일어나는 일:
1. `batch DELETE` → `mock-router.ts:1789` 의 *"입고 transaction 삭제 시 발주 status 원복"* 로직이 자동으로 `purchase_orders.status = "발주"`, `received_at = null` 로 되돌림
2. 새 transaction INSERT — row 의 `orderId === null` 인 채로
3. `line 246-254` 의 status 재갱신 단계는 `orderIds.length === 0` 이라 SKIP
4. → 발주는 미입고로 회귀

#### 수정

```ts
function parseNote(note: string | null | undefined): { orderId: number | null; memo: string } {
  if (!note) return { orderId: null, memo: "" };
  const m = note.match(/^발주 #(\d+) 입고완료(?:\s*\/\s*(.*))?$/);
  if (m) return { orderId: Number(m[1]), memo: (m[2] ?? "").trim() };
  return { orderId: null, memo: note };
}
```

useEffect 안 row 로딩 시 `orderId: parsed.orderId`, `remark: parsed.memo`. `setReference(parseNote(target.note).memo)` 로 "참조" 입력란도 사용자 메모만 표시(태그 누출 차단). 미일치 패턴은 그대로 memo 취급(레거시 안전).

### 회귀 버그 2: 입고/출고 수정 시 단가 미보존

#### 원인 3중 누락

**A. `save()` POST body 에 `unitPrice` 누락** — `InboundEntry.tsx:235-242` / `OutboundEntry.tsx:259-268`. 화면 입력 단가가 DB 로 전송 안 됨.

**B. 수정 모드 로드 시 `unitPrice: 0` 고정** — `InboundEntry.tsx:97` / `OutboundEntry.tsx:94`. transaction 에서 받아온 `t.unitPrice` 무시 → 진입할 때마다 단가 빈 칸, 매번 재입력 필요.

**C. RPC `add_transaction` 가 `p_unit_price` 인자 없음** — `mock-router.ts:supabaseAddTransaction` 시그니처에 unitPrice 자체가 없음. 새 transaction 이 항상 NULL/RPC 기본값(자재 마스터 `buy_price`/`sell_price`)으로 저장됨.

#### 수정 (3 files)

| 파일 | 변경 |
|------|------|
| `InboundEntry.tsx` | row 로드 시 `unitPrice: t.unitPrice ?? 0`. save POST body 에 `unitPrice: r.unitPrice \|\| 0` |
| `OutboundEntry.tsx` | 동일 패턴 |
| `mock-router.ts` `supabaseAddTransaction` | 시그니처에 `unitPrice?: number \| null` 추가. RPC 호출 직후 `unitPrice > 0` 일 때만 `transactions.unit_price` 컬럼 별도 UPDATE. 0/미지정이면 RPC 가 채운 자재 마스터 기본값 보존 |

RPC SQL 함수는 그대로 두고 클라이언트 측 추가 UPDATE 로 우회 — 외부 담당자 마이그레이션 요청 불필요.
