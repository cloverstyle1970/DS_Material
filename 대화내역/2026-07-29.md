## 3. TBM 전면 개편 (`e9bcf33`)

### 3-1. 폭염 예방 · 환경지표 · 휴게 실시

`TBMWriteForm.tsx` — 공사구분/부속 블록과 작업 내용 사이에 다음을 추가:

2. **🌡️ 환경 지표** — 작업일지와 동일 UX:
   - 상단 스크래치 입력행(온도·습도·체감온도·지역) + 📡 실시간 기상정보 / 💾 내용저장 두 버튼
   - 온도·습도 입력 시 `calcApparentTemperature`로 체감온도 자동 계산 (수동 값 유지)
   - `heatStressLevel` 4단계 색상 배지 + 조치 안내 배너

3. **🥵 온열질환 예방 휴게 실시 확인** — 시작/종료 24H `TimeText`(작업일지 컴포넌트 재사용), 휴게방법, + 행 추가

저장 로직에도 `heatPrevention` 가드 → 언체크 상태면 두 테이블 insert 자체를 건너뜀.

### 3-2. 참가자 서명 통합 (작업일지와 동일 방식)

**핵심 변경**: `participants: UserMini[]` (검색+칩) → `workers: Worker[]` (성명+개별 서명 카드).

- `workers[0]`은 로그인 사용자 자동 세팅 + 삭제 불가 (`(작성자 자동)` 표시)
- 기본 2행, `+ 참가자 추가`로 증설, 3인 이상일 때만 삭제 가능
- 성명은 `datalist`로 재직 사원 자동완성
- 각 참가자 카드에 개별 `SignaturePad`
- **작성자 서명 필수**, 다른 참가자는 미서명 허용 → 저장 시 자동 알림 발송(제목: TBM 서명이 필요합니다)
- 서명한 사람은 `tbm_participants.confirmed_at` 즉시 채움
- 기존 단일 [작업책임자 서명] 섹션 삭제 (`workers[0]`이 그 역할 흡수, `tbm_records.signature_url`엔 workers[0] 서명 저장 — 상세/인쇄 하위호환 유지)

**검증 강화**:
- 최소 2인 (작성자 포함)
- 모든 참가자 성명 필수
- 각 참가자 `user_id` 매칭 필수 (`tbm_participants` PK가 tbm_id+user_id라 unresolved면 저장 실패 방지)
- 중복 사원 방지

`sigPadRef`, `participants`, `participantSearch`, `participantHighlighted`, `participantSearchRef`, `filteredParticipants` 모두 제거.
