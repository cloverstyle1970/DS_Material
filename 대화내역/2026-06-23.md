## 1. 출고전표 S/N 수정모드 그룹핑 (커밋 `009a4f8` 일부)

### 진단

사용자 보고: "출고전표에서 S/N 입력했는데, 수정모드로 들어가면 S/N 정보가 비어 보인다."

`add_transaction` RPC (`migration-outbound-free-serial.sql`)의 동작:
- 한 화면 행에 S/N N건 + 잔여 비추적 M건이면 → `transactions` 테이블에 **(N + M)개 row** 생성, 각 row의 `qty=1`, `serial_no`는 추적행만 채워짐
- 모두 같은 `batch_id`, `transaction_no`, `note` 공유

이전 수정모드 로딩(`OutboundEntry.tsx:116-136`)은 siblings를 각각 별개 화면 Row로 펼침 → 자재가 N+M개 행으로 분리, 그 중 M개 행의 S/N 컬럼이 비어 보이는 상태.

### 적용

`OutboundEntry.tsx` 수정모드 로딩에서 그룹키 함수 도입:

```ts
const groupKey = (t, inboundRef, memo) =>
  `${t.materialId}|${t.elevatorName ?? ""}|${t.unitPrice ?? 0}|${!!t.requiresReturn}|${inboundRef ?? ""}|${memo}`;

const groups = new Map<string, Row>();
for (const t of siblings) {
  const parsed = parseOutboundNote(t.note);
  const key = groupKey(t, parsed.inboundRef, parsed.memo);
  const existing = groups.get(key);
  if (existing) {
    existing.qty += t.qty;
    if (t.serialNo) existing.serialNos.push(t.serialNo);
  } else {
    groups.set(key, { /* 신규 Row, serialNos: t.serialNo ? [t.serialNo] : [] */ });
  }
}
```

같은 입력 단위로 1행 복원. 저장 로직은 변경 없음 — 기존 `editBatchId` 단위 DELETE 후 재삽입이므로 RPC가 다시 분할 저장하여 정합성 유지.

## 2. 견적요청 목록 — TK 색상 + 검색 + DS/TK 토글 (커밋 `009a4f8` 일부)

### TK 자재 표시

`quote_requests` 테이블 자체에는 DS/TK 구분 컬럼 없음. 한 번의 `IN` 쿼리로 모든 요청의 `quote_request_items.material_id` 로딩 → `isTkMaterial()`(첫 글자 ≠ 'D')로 판정 → TK 자재가 한 건이라도 포함된 요청 ID를 `tkRequestIds: Set<number>`에 모음.

행 렌더 시 5개 텍스트 셀(접수일시·현장·호기·작업명·신청자)에 `TK_TEXT_CLASS`(text-blue-600 / dark:text-blue-400) 적용. 구분 배지도 "TK 견적요청"으로 라벨 변경.

### 검색 + DS/TK 토글

두 단계 `useMemo` 로 분리:

```ts
// 1단계: 검색어 + DS/TK 토글
const searchFiltered = useMemo(() => {
  return list.filter(r => {
    if (matType === "TK" && !tkRequestIds.has(r.id)) return false;
    if (matType === "DS" && tkRequestIds.has(r.id)) return false;  // 순수 DS만
    if (q) {
      const hay = [r.request_no, r.site_name, r.elevator_name, r.work_title,
                   r.requester_name, r.requester_dept].filter(Boolean).join(" ").toLowerCase();
      if (!hay.includes(q)) return false;
    }
    return true;
  });
}, [list, query, matType, tkRequestIds]);

// 2단계: 상태 필터
const filtered = useMemo(
  () => filter === "전체" ? searchFiltered : searchFiltered.filter(r => r.status === filter),
  [searchFiltered, filter]);
```

상태 필터 칩의 카운트는 `searchFiltered` 기준 — 검색·토글 적용 후 상태별 분포가 표시되어 사용자가 결과 분류를 빠르게 파악.

UI: 헤더 우측에 검색 input + DS/TK 토글(자재 토글과 동일한 시각 패턴: DS 빨강, TK 파랑, 전체 회색).

## 4. 자재비 영역 + 자재 검색 드롭다운 다듬기 (커밋 `009a4f8` 일부)

### 폼 영역 확대

- 폼 컨테이너: `max-w-6xl`(1152px) → **`max-w-[1600px]`**
- `DEFAULT_ROW_COUNT`: 5 → 10 → **3** (사용자 피드백 반영, 기본 3행으로 시작)

### 헤더 sticky 고정

원래 thead에 `sticky top-0` 만 줬는데, 부모 `<div className="overflow-x-auto">`가 sticky의 containing block이 되어 페이지 viewport가 아닌 그 div 내부에서만 sticky 동작 → 그 div의 세로 높이가 부족해 실질 효과 없음.

**`overflow-x-auto` 제거** → 페이지 자체가 scrolling ancestor 가 되고 thead가 viewport 상단에 붙음. 각 `<th>`에 직접 `bg-gray-50 dark:bg-gray-700` 추가 (sticky 시 tr 배경이 일부 브라우저에서 투명해지는 문제 방지) + `shadow-sm`.

### 자재 검색 드롭다운

- 너비: `w-96`(384px) → `w-[32rem]`(512px)
- 높이: `max-h-52` → `max-h-[48rem]` → **`max-h-[16rem]`** (5건 가시 + 나머지 스크롤)
- **색상 우선순위 (`material-style.ts` 단일 진리원)**:
  - 🟢 수리품(`isRepairMaterial`: D...R 또는 A...) → 자재명·코드 `text-green-600 / dark:text-green-400` + `RE` 뱃지
  - 🔵 TK 자재(`isTkMaterial`: 첫 글자 ≠ D) → `TK_TEXT_CLASS`
  - 기본 → 기존 회색 유지

## 7. Dev 서버 OOM 회피 (커밋 `a1f68a6`)

### 패턴

세션 중 4회 OOM 발생:

```
FATAL ERROR: Ineffective mark-compacts near heap limit
Allocation failed - JavaScript heap out of memory
```

압박 신호: `Compiled in 59.6s → 46.9s → 131.3s` 처럼 점점 느려지다 죽음. 16GB(Node 기본 한도) 도달 후 다이.

### 시도 단계

1. **재시작만** — 임시방편, 누적 시 또 죽음
2. **24GB 힙 상향** (`cross-env NODE_OPTIONS=--max-old-space-size=24576`) — 약 1시간 51분 가동 후 또 죽음 (`22935.3 / 24628.7 MB`). 한도는 정상 적용 확인, 누수율 자체가 빨라 단순 비례 증가일 뿐.
3. **Webpack 전환** (`next dev --webpack`) — 현재 적용. Next 16에서 정확한 옵션은 `--no-turbopack`이 아닌 **`--webpack`** (`next dev --help` 확인). Turbopack의 dev 누수 회피.

### 최종 적용

```json
"scripts": {
  "dev": "cross-env NODE_OPTIONS=--max-old-space-size=24576 next dev --webpack"
}
```

`cross-env`를 devDependency에 추가 (Windows PowerShell이 `VAR=값 cmd` prefix를 받지 못함).

### 부수: cross-env의 exit 127 이슈

webpack 모드 첫 시도에서 `Next.js 16.2.4 (webpack) ✓ Ready in 723ms` 출력 직후 종료(exit 127). 두 번째 시도에서 정상. 재현성 낮은 시그널 처리 이슈로 보임.

## 8. 입출고 참조 리스트 시인성 강화 (커밋 `a1f68a6`)

`InboundEntry`의 발주서 참조 팝업과 `OutboundEntry`의 입고내역 참조 팝업 양쪽에 동일 패턴 적용:

| 항목 | 이전 | 개선 |
|---|---|---|
| 본문 글자 | `text-xs` (12px) | **`text-sm`** (14px) |
| 행 패딩 | `py-1.5` | **`py-2`** |
| 헤더 | `bg-gray-50 font-medium text-gray-700` | **`bg-gray-100 font-bold text-gray-800`** + `border-b-2` |
| 발주참조번호 | `text-blue-600 font-medium` | **`text-blue-700 font-bold`** |
| 자재코드(일반) | `text-slate-500` | **`text-slate-700 font-semibold`** |
| 품목명(일반) | `dark:text-gray-200`만 | **`text-gray-900 font-semibold`** + 다크 |
| 수량·단가 | `dark:text-gray-300` | **`font-bold` + 진한 색상** |
| 거래처·현장·신청자 | `dark:text-gray-300` (light 미명시) | **`text-gray-800 dark:text-gray-100 font-medium`** |
| 호버 | 회색 또는 orange-50 | InboundEntry: `bg-blue-50/40`, OutboundEntry: `bg-orange-50` 유지 |
| 빈 상태 | `text-xs text-gray-400` | **`text-sm text-gray-500 font-medium`** |

TK 자재의 `TK_TEXT_CLASS`(파란색)는 양쪽 모두 그대로 유지.
