## 1. Web Push 알림 — 코드·DB 정합화

### 시작점
사용자가 `/me` 내 대시보드의 **브라우저 푸시 알림** 토글에서 [구독] 클릭 시 외부서버에서 "VAPID 공개키 미설정", 개발서버에서 "Failed to fetch" 오류 보고.

### 원인 1 — Edge Function 미배포
```
push-subscribe: HTTP 404
push-send:      HTTP 404
```
로컬 `supabase/functions/`에 코드만 있고 `supabase functions deploy`된 적 없음. 클라이언트의 fetch가 OPTIONS preflight 404로 CORS 오류 → "Failed to fetch"로 surface.

### 원인 2 — 코드와 신DB 스키마 불일치
실제 신DB의 `push_subscriptions` 컬럼을 직접접속(`postgres.bbnmxwpacdfqvicybhau`)으로 probe해보니 코드 가정과 완전히 다름:

| 가정한 컬럼 | 실제 컬럼 |
|------------|-----------|
| `user_id` | `account_id` |
| `p256dh`, `auth` (분리) | `subscription` (JSON 한 컬럼에 통합) |
| `user_agent` | 없음 |

또한 `push-send` 함수가 `from("users").select("push_enabled")`를 호출 — 신DB는 사원 테이블이 `accounts`인데 `users`(Supabase Auth 시스템 테이블)를 조회하는 버그. 기존 `migration-add-push-subscriptions.sql`도 `users(id)` 참조라 신DB와 어긋남.

push_subscriptions 테이블엔 이미 71행이 들어있었음 — men.daesol.kr 등 다른 사이트가 같은 신DB를 공유하며 만든 구독.

### 수정 (커밋 `86186fb`)
- `push-subscribe`: upsert 시 `user_id` → `account_id`, `p256dh/auth` 분리 컬럼 제거 → `subscription` JSON 한 컬럼에 `{endpoint, keys:{p256dh,auth}}` 그대로 저장
- `push-send`: `from("users")` → `from("accounts")`, select 컬럼을 `(id, endpoint, subscription)`로 변경, webpush에 넘길 때 `subscription` JSON에서 keys 풀어내기
- `migration-add-push-subscriptions.sql`: `accounts.push_enabled/notifications_enabled` + `push_subscriptions(account_id, subscription JSONB)` 기준으로 재작성, idempotent

### 적용 (직접접속)
신DB는 외부 담당자가 관리(Dashboard 권한 없음)지만 DB 비밀번호로 직접접속 적용 가능. `scripts/apply-migration.mjs`로 실행:
```
accounts_push_on: 57   (push 토글 ON 계정 수)
accounts_inapp_on: 58  (인앱 알림 ON 계정 수)
total_subscriptions: 71
```

### Edge Function 배포 — 유지보수팀 의뢰
배포(`supabase functions deploy`)는 Supabase 프로젝트 권한이 필요한데 사용자는 미보유. DB 비밀번호로는 함수 배포 불가. `next.config.ts`가 `output: "export"`라 Node 서버로 우회 불가능 — Edge Function이 유일한 서버 사이드 실행 경로.

**유지보수팀용 단독 문서 작성** (커밋 `4accd50` → 보강 `75409fb`):
- `docs/deploy-push-functions.md`
- 사전 준비(CLI 버전·repo 클론·로그인) → 배포 2줄 → 시크릿(CLI/Dashboard 두 경로) → curl 검증
- VAPID 시크릿 값은 .env*가 .gitignore 대상이라 문서에 placeholder만, 별도 보안 채널로 전달 안내
- 트러블슈팅 표(5개 증상)

### 미해결
- Edge Function 2개 배포 — 유지보수팀 회신 대기
- prod 빌드(npm run build)는 본인이 하므로 `.env.local`의 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`가 자동 인라인됨. 별도 작업 없음.
- 배포 후 검증: dev에서 [해제] → 새로고침 → [구독] → [테스트 알림 보내기]

## 2. 개선요청 게시판 추가

### 배경
사용자가 "사이드바에 게시판 메뉴 추가하고 개선요청을 등록하게 검토" 요청. 8개 색상 그룹 어디에도 안 맞는 새 도메인이라 별도 그룹 신설.

### 결정 (사용자 합의)
- **스코프**: 개선요청 메뉴 하나만 먼저. 공지/Q&A는 향후 같은 그룹에 얹기.
- **권한 모델**: 전직원 read/create, 작성자·admin만 수정·삭제, 상태 변경·응답은 admin만.
- **데이터 모델**: 카테고리/댓글/첨부 없이 단일 테이블로 출발. 상태 워크플로우만 컬럼으로.

### DB (커밋 `d8882aa`)
```sql
CREATE TABLE improvement_requests (
  id, author_id (→accounts), title, content,
  status TEXT CHECK IN ('접수','검토중','반영','거부') DEFAULT '접수',
  response TEXT, assignee_id (→accounts, nullable),
  created_at, updated_at
);
-- updated_at 자동 갱신 트리거(공유 함수 set_updated_at_now)
-- RLS allow_all (개발 표준)
```

### 권한 부여 — 마이그레이션에서 일괄
신DB 직접접속 probe 중 발견: **`accounts.permissions`는 `jsonb`인데 `permission_groups.permissions`는 `text[]`** — CLAUDE.md의 `text[]` 기록 부정확. 두 테이블에 동일한 SQL을 쓰면 `COALESCE types jsonb and text[] cannot be matched` 오류로 즉시 실패함.

분기 작성:
- `accounts` (jsonb): `permissions || jsonb_build_array('menu:/board/improvements:read')`, 중복 체크 `permissions ? 'menu:...'`
- `permission_groups` (text[]): `permissions || ARRAY['menu:...']`, 중복 체크 `'menu:...' = ANY(permissions)`

결과: 59개 계정 모두 read 권한 보유(57개에 신규 추가, 2개 admin은 기존 통과), 7개 권한그룹 시드도 패치.

### UI
- `/board/improvements` 단일 페이지 (`src/components/board/ImprovementRequestsClient.tsx`)
- 상단: 상태 필터칩(전체/접수/검토중/반영/거부) + [+ 등록]
- 목록: 카드형(상태 뱃지, 제목, 내용 2줄, 작성자, 날짜, 답변 여부)
- 등록 모달: 제목·내용 입력
- 상세 모달:
  - 본문 표시 → 작성자·admin은 [수정] [삭제]
  - admin 전용: 상태 select + 응답 textarea + "상태·응답 저장"
- 사이드바 신규 그룹 `text-teal-400` 색상, 아이콘 `📮`
- `PERMISSION_MENUS`(권한그룹 UI용)에도 게시판 카테고리 추가

### 검증
- `tsc --noEmit` 통과
- dev 서버 컴파일 `/board/improvements 200 OK`
- 사용자 브라우저 확인 완료

## 3. CLAUDE.md 정정 (커밋 `59a6959`)

위 게시판 마이그레이션 작성 중 드러난 사실:
- `accounts.permissions` → 실제는 **jsonb** (배열 사용)
- `permission_groups.permissions` → **text[]**

CLAUDE.md 64행 `accounts.permissions: text[]` 가 단일 진리원 → `accounts.permissions: jsonb`로 정정하고 `permission_groups`와의 타입 차이도 한 줄에 함께 명시.

같은 내용을 자동 메모리에도 저장(`project_permissions_column_types.md`) — 다음 세션 Claude가 동일 시행착오 안 하도록.
