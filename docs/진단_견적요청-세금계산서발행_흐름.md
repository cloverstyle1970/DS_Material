# 진단: 자재 신청(견적요청) → 세금계산서 발행 흐름

> 작성일 2026-06-27 · 코드/DB 점검 결과 · **추후 보완 과제 기록용** (이 문서 작성 시점 기준이며 코드 변경 시 갱신 필요)

## TL;DR

코드상 흐름(견적요청 → 견적서 → 발행 → 입금)은 **설계·구현·연결이 완결**되어 있으나, 실제로는 **거의 사용되지 않는다.** ~~가장 큰 문제는 핵심 테이블(`invoices`,`payments`) 미적용~~ → **2026-06-27 두 테이블 적용 완료(방향 A 채택)로 시스템 발행·입금 기능 정상화.** 다만 실제 발행·입금·미수는 여전히 외부(이카운트/홈택스) + 엑셀(`sales_invoices` 47,622건)에서 이뤄지며, 시스템 발행(`invoices`)과 엑셀(`sales_invoices`)의 **연결·일원화는 미해결**(잔여 과제 §4).

## 1. 코드로 구현된 "시스템 견적 흐름" (검증됨)

```
① 견적요청   ClaimEntryClient(유상견적요청) → quote_requests(+items)  status=신청
        │   자재담당 알림
② 견적서    QuoteEntryClient?fromRequest=N → quotes(+quote_items / quote_labor_lines)
        │   저장 시 quote_requests.quote_id 연결 + status=견적발행  (QuoteEntryClient.tsx:907-910)
③ 결재     quotes.status  작성중 → 발행 → 승인
④ 자재신청   QuoteDetailClient(승인 후) → material_requests(quote_id FK, request_type='유상견적')
        │   RequestsClient 출고처리 → transactions, progress_state 자재신청 → 자재출고
⑤ 발행     QuoteDetailClient.issueInvoice(승인+유상) → invoices(quote_id FK, invoice_type)
        │   세금계산서 발행 시 quotes.progress_state = 세금계산서발급
⑥ 입금     payments(quote_id FK) → 누적입금 ≥ 합계 → progress_state = 입금완료
```

- 진행상태(`quotes.progress_state`) 6단계: `미시작 → 자재신청 → 자재출고 → 세금계산서발급 → 입금완료 → 종료`
- 발행 화면: `TaxInvoiceClient`(세금계산서) / `DeliveryNoteClient`(거래명세서) — `invoices.id`로 로드, `window.print()` 출력
- 링크 구조(`quote_requests ↔ quotes ↔ invoices ↔ payments`)는 코드·스키마상 모두 연결됨

  - `invoices`(17컬럼) / `payments`(13컬럼), 인덱스·RLS(allow_all)·CHECK·FK(`quote_id→quotes`) 정상, PostgREST reload 완료.
  - 이제 견적 상세에서 🧾 세금계산서 / 📄 거래명세서 발행 + 입금 등록 정상 작동.

### ② [구조] 시스템 발행 = 사내 양식 인쇄일 뿐
- `invoices.external_ref`(홈택스/위하고 발급 ID)·`doc_url`(PDF)은 항상 NULL.
- 국세청 실제 발행이 아니라 브라우저 인쇄용 사내 양식. 실제 발행은 이카운트/홈택스에서 별도.

### ③ [단절] `sales_invoices`(계산서 발행내역, 47,622건)가 `quotes`와 연결 안 됨
- `sales_invoices`에 `quote_id` 컬럼 **없음**. 엑셀 import 전용 독립 테이블.
- 어느 견적요청/현장 신청이 어느 세금계산서로 발행·입금됐는지 **추적 불가**.

### ④ [실사용 격차] 견적 흐름은 사실상 테스트 수준

| 테이블 | 행수 | 의미 |
|--------|------|------|
| quote_requests | 6 (견적발행 3) | 거의 미사용 |
| quotes | 3 (승인 1) | 거의 미사용 |
| invoices / payments | 0 | 2026-06-27 적용 완료(빈 상태) |
| material_requests | 5 | 소량 |
| **transactions** | **651** | 실사용(출고) |
| **sales_invoices** | **47,622** | 실제 업무 데이터(엑셀) |

→ 현장 운영은 **자재청구/출고(transactions) + 엑셀 회계(sales_invoices)** 중심. 시스템 견적→발행 흐름은 실질적으로 사용되지 않음.

### ⑤ [기존 이슈] 공급받는자 사업자번호 미입력
- 발행 시 `invoices.customer_biz_no` 입력 UI가 없어 NULL 저장.

## 3. 흐름이 끊기는 지점

```
견적요청 ─✅─ 견적서 ─✅─ (자재신청/출고) ─❌ invoices 테이블 없음 ─ 세금계산서 발행
                                                             ╎ (연결고리 없음)
실제발행(이카운트/홈택스) ─ 엑셀 ─ sales_invoices(47K) ─ 입금/미수(pay_status)
```

사실상 **두 개의 평행 세계**가 존재:
- **시스템 견적 흐름** (quote_requests→quotes→invoices→payments): 코드는 완결, 그러나 invoices/payments 미적용 + 실사용 없음
- **실제 회계 흐름** (이카운트/홈택스 발행 → 엑셀 → sales_invoices): 실제 발행·입금·미수 관리, 그러나 시스템 견적과 무연결
